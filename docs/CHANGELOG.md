## [Unreleased]

### Fixed

- Solves are no longer lost when background start-up fails. Every solve waits on
  `initPromise` before it is written, and that promise was resolved only as the last
  statement of `init()`. Four of the steps before it — `initDebug()`,
  `applyFirstRunDefaults()`, `initMCPConfig()` and `initializeReviewQueueStore()` — were
  awaited with no `.catch()`, and neither call site guarded `init()` either. A throw in
  any of them left the promise pending for the life of the service worker, so
  `handleSolved()` hung on its first line: no record was saved, no error surfaced, and
  solved problems simply never appeared in the library. The promise now settles in a
  `finally`, which trades a degraded worker for a hung one — storage does not depend
  on init, so the solve is still written when a later start-up step fails.

- Linking a GitHub repository that has no commits no longer breaks onboarding, and
  committing into one no longer fails forever. Both paths detected the empty repository
  correctly — the ref lookup answers `409 Git Repository is empty` — and then tried to
  author its first commit through the Trees API, omitting `base_tree` and `parents` to
  make a root commit. That could never have worked: a repository with zero commits
  refuses every git-data write, so `POST /git/blobs` and `POST /git/trees` answer the
  same 409 as the lookup that detected it. Onboarding died at the tree call, and a
  solve into a freshly created empty repo failed for as long as it stayed empty. Both
  now seed one file through `PUT /contents` — the only endpoint such a repository
  accepts — which writes a genuine root commit and creates the branch; everything after
  that runs as the ordinary non-empty case. The seeded README is overwritten by the
  real generated one in the same commit, so no placeholder is left behind. A ref lookup
  that answers 404 is a different case — the branch is missing but the repository has
  commits elsewhere — and still takes the parentless-commit path, which is correct
  there and would break if seeded.

## [1.9.0] — 2026-09-03

### Added

- A roadmap that reads your ledger and tells you what to do next. Three surfaces, all computed in the browser from the same `index.json` everything else reads — no server, no account, no upload.

  **What to fix first** (Analytics) is at most three findings and each one carries the number behind it, so what you leave with is "four core topics at zero", not "some gaps in graph algorithms". It ranks absent foundations above absent core topics, then an Easy-heavy mix, then topics you solved once and have not returned to in months. It can come back empty, and an empty report is a real result rather than a bug.

  **The plan** (Behaviour Bank → Roadmap) takes an interview date, hours a day and a target role, and orders the work by what each topic is built from — Sorting before Binary Search, Two Pointers and Hash Table before Sliding Window, Binary Tree before DFS before Graph — instead of by how often a topic comes up, which would put Dynamic Programming first and is the worst advice available. The next seven days name actual problems, mapped to NeetCode 150 (150 problems, grouped) and Striver's A2Z (18 steps, linked rather than transcribed); everything past that is a weekly theme, because the queue is rebuilt as solves land and naming five problems for the third Tuesday from now is false precision. Problems you have already solved are scheduled for revision at 7, 21 and 60 days — the part that makes a compressed plan hold under pressure, and the part most roadmaps omit. If the work does not fit before your date, it says so with both numbers and names what falls off the end, rather than truncating quietly and presenting the remainder as a complete plan.

  **Where the gaps are** now ranks never-touched topics by tier and dependency position. They were always rendered; they were ordered by a JavaScript object's key order, so "Suffix Array", "Data Stream" and "Iterator" took the first three of twelve slots and Backtracking, Heap and Trie fell off the end. It also names the three topics deliberately not listed — Monotonic Stack, Monotonic Queue and Intervals — and what they are counted under, because a report that silently omits something you believe in reads as broken.

  Two things are excluded from the algorithm counts on purpose: SQL, Database, Pandas and Shell solves, which are real work but not what an algorithm interview measures, and any topic outside the reference set, because a zero nobody is asked about is not a gap.

- Topics are a tree now, not a flat list. Monotonic Stack sits under Stack, Binary Search Tree under Binary Tree under Tree, Matrix and Prefix Sum under Array, Reservoir Sampling under Randomized under Probability under Math — 89 topics, 19 families, every canonical name the extension already knew about placed exactly once. The graph draws the containment as its own edge, so the tags are linked to each other and not only to your problems.

  This is a third relation, kept deliberately separate from the two that already existed. An alias fold (`arrays` → `Array`) is destructive: the alias is gone after normalisation. A prerequisite (`Sliding Window` needs `Two Pointers`) is an ordering, not a containment — Tree is therefore **not** filed under Graph, because you learn traversal on a tree first and folding one into the other would hide the Graph zero the gap report exists to surface. Containment rolls a count up while leaving the specific topic visible under its own name. Each problem is counted once per topic no matter how many of its tags land in the same branch, so a well-tagged solve does not inflate its family.

  Every placement is yours to overrule, in Settings → Platforms → Topic Hierarchy: move any topic under any other, send it to the top level, or reset it to the built-in call. Topics you invented through a custom mapping are in the tree too — hung under Ad Hoc until you place them, because a tag that does not render is a tag you cannot re-parent. The dropdown never offers a topic's own descendants, so a cycle cannot be built from the UI; the walks are cycle-safe regardless, since these settings are also editable by hand and writable by AI healing, and a bad edge should cost a wrong answer rather than a frozen tab.

- Roughly 54 more canonical topics and their aliases, so the three platforms' vocabularies land on shared names instead of parallel ones. Codeforces passes its tags through untouched, which meant `sortings`, `dfs and similar`, `flows`, `graph matchings`, `constructive algorithms`, `probabilities`, `bitmasks`, `2-sat`, `string suffix structures`, `expression parsing` and `schedules` each title-cased into a topic of their own, sitting beside the LeetCode topic that means the same thing. Note this only affects tags read from here on: a solve already in your ledger was normalised when it was written. The self-heal pass re-tags them the next time it runs against those problems.

- The GitHub Pages report has a Knowledge Graph section, the same picture the library's Graph tab draws: topic hubs coloured by mastery (solve volume × recency, 90-day half-life, decay clocked from the second-most-recent solve so one stray solve does not repaint a rusty topic), problem dots coloured by difficulty, and the unsolved similar problems LeetCode attaches to your solves shown as hollow ghost suggestions. Drag to pan, scroll to zoom, hover for details, click a problem to open it on its platform. Rendered on a plain canvas from the same `index.json` the rest of the report reads — no library, no network call, and it respects the report's light/dark toggle. Existing repos pick it up through the usual report-update flow in Settings → Git.

- An AI provider that needs no API key and no account: **Manual (copy & paste)**. Pick it and CodeLedger stops making AI requests entirely — instead it shows you the exact prompt it would have sent, you copy it into whichever chat you already pay for or already have open, and paste the reply back. The answer is stored and committed like any other review.

  It is deliberately unavailable in the two places where nobody is watching. The service worker runs a review after a solve, sometimes with the tab already closed, so it filters this provider out of both the primary chain and the automatic fallback chain rather than calling it and waiting; it is also absent from `AI_FALLBACK_CHAIN`, so it can never be reached by failover. Where it is reachable — the library chat, a problem's chat, and the floating panel on a problem page — a cancelled exchange raises an error instead of returning an empty string, because an empty review would otherwise be written into your repository as that solve's review.

  The privacy list describes it truthfully: destination "your clipboard", nothing sent, and enabling it does not move your headline privacy tier — CodeLedger makes no request for it. What the chat you paste into does with the prompt is between you and them, and the note says so rather than claiming the answer is free or private.

- `docs/THREAT_MODEL.md` — what CodeLedger defends against, what it explicitly does not, and the residual risks ranked. The second half is the point of it: a compromised NeetCode or takeuforward page can forge an accepted submission and there is no shared secret that fixes it; a compromised page on any supported platform can fabricate a solve through the DOM; tokens and AI keys are readable by anyone holding the OS profile; a leaked GitHub token reaches every repository in the granted scope, not only the ledger; `index.json` is unsigned, so sync can tell you two records disagree but not which is authentic, and there is no size cap on it; the AI endpoint check validates the scheme and not the host; and the OAuth flow trusts whoever operates the worker. Nothing in it is aspirational — every defence claimed on the first half is covered by a test that fails without it.

- An error boundary around the library and the welcome page. A component that throws while rendering used to take the whole page down to a blank white screen with the reason visible only in DevTools; you now get the message, the stack, and a Reload or Try again button, plus a reminder that the solves are in local storage and in your repository rather than on that screen. It catches render and lifecycle errors only — an error thrown from an event handler, a timer or an unawaited promise never passes through the renderer, so no boundary in any framework sees those, and they still go to the console.

### Changed

- One security policy instead of two. `.github/SECURITY.md` and the root `SECURITY.md` were separately maintained and disagreed: the `.github` copy — the one GitHub actually surfaces — promised a 72-hour acknowledgement, 7-day triage and a 14-day fix estimate for a one-person project, and pointed reporters at a Chrome Web Store listing that does not exist. The root copy said honestly that no response time is guaranteed, and was never shown to anyone. The `.github` copy is now the single policy, carrying the honest expectations, both private reporting channels, sync ingest added to scope, and a pointer to the threat model; the root file is a redirect to it.

- Backups now carry the same set of settings cross-device sync does, decided by one shared allow-list instead of two hand-maintained denylists. A snapshot taken before this release could contain anything the denylists failed to name — `openai_apiKey` slipped past, because the check spelled the word "key" in lowercase and that setting does not. Settings outside the allow-list are no longer written into a backup, and no longer applied when one is restored; your preferences, theme, roadmap and platform configuration are unaffected, and credentials were never meant to be in there in the first place.

- The Firefox manifest declares `websiteContent` as required data collection. It said `["none"]`, while the add-on's core function reads the user's submitted solution from the page and sends it to GitHub — and, once the user enters an AI key, to that provider as well. `none` was a stronger claim than the code supports, and it is the kind of claim a reviewer checks. `technicalAndInteraction` stays optional and off by default, which is what the telemetry counter actually is.

- Every store listing document now matches the code it describes. The corrections, each verified against a file rather than reasoned about:
  - `docs/store/submission.md` opened by saying Chrome was not yet published. It has been live since 2026-06-15, at 1.4.5, with roughly ten users on a build that predates every security fix since. The document now says so, and adds the sequencing fact that matters more: the next update adds `tabs`, which raises a new permission warning, so it is a full re-review with existing installs disabled until each user re-accepts.
  - The `storage` justification in `chrome.md` ended "No other data leaves the browser" and the one in `edge.md` said all data stays local or in the user's own repo. Both were contradicted further down their own file by the AI providers, and by telemetry in the Chrome case. `storage` now claims only what it does, and points at the destination list.
  - The "Website content" data-usage answer was **No** in both forms on the grounds that code goes only to the user's own repository. Enabling AI review sends the solution to a third party, so it is now **Yes** with that case named.
  - `edge.md` said the opt-in telemetry counter was the only call not covered by a host permission. Three others are not: `raw.githubusercontent.com`, `img.shields.io` and `mermaid.ink`. All three are now enumerated in all three listings, with the four distinct uses of the first one spelled out — the party comparison was the only one previously described.
  - `mermaid.ink` appeared in `PRIVACY.md` and in the extension's live privacy panel but in no store file at all.
  - The alarm justifications enumerated six alarms; the service worker creates seven. The bulk-import resume alarm is now described.
  - The `codeledger.vkrishna04.me` justification named two uses. There is a third — the presence-marker content script on the landing page.
  - The vendored-library lists named Preact, htm and Chart.js and omitted vis-network, which is the second-largest file in `src/vendor/`. All four are named, with a pointer to `BUILD.md` for the reproducing commands.
  - "The access token is stored securely" implied encryption that `storage.js` does not perform. It now says what is true: extension-local storage, readable only by this extension, not additionally encrypted.
  - The repository-layout example showed `lc-two-sum.md` as the description file. `path-builder.js` always writes `README.md`, so that GitHub renders it when browsing the folder.
  - The topic radar was attributed to the GitHub Pages report in four places. It is in the extension's Analytics view; the Pages report has the heatmap, difficulty and velocity charts.
  - "No third-party image service" was true of the default SVG badges and false of the shields.io opt-in, which is a shipped feature. Both are now described, including why shields needs a public repo.
  - "Share a link and it opens for anyone" omitted that the share card is only offered when badges are on, Pages is configured and the repo is public — a private repo has no file to link to.
  - takeuforward was described as "built and tested" like the other two beta platforms. Its judge is behind a TUF+ subscription that was not available, so the accepted-verdict shape is inferred rather than observed, exactly as the source comments say. The listings say that now, and the submission checklist adds a reviewer note about it — a reviewer without a subscription cannot exercise that platform, and "non functional" is the category the Chrome listing was already rejected under once.

### Fixed

- Repository maintenance refuses to run when this device has nothing stored. Force Rebuild, Reset and the layout migration all work the same way: read every solve out of local storage, rebuild the repository from that, and delete whatever the rebuild did not produce. That is correct while local storage holds your solves. It does not on a second device — install the extension, link the repository you already have, and until the first sync pull lands IndexedDB is empty, so "rebuild from local" means "delete every solution and commit nothing back", against what was at that moment the only copy. All three now stop with a message naming how many files they would have deleted and telling you to sync first. Force Rebuild was the worst of the three and is the reason this is a fix rather than a hardening: its clear was a separate commit issued _before_ it read local storage, so the wipe landed first and anything failing afterwards — including the empty store itself — had nothing left to restore it. The read now happens first. None of this is reachable from a web page: all three message types are off the content-script allow-list and `externally_connectable` is unset, so the trigger was always your own click on your own device.

- "Set up repository →" on the welcome page works every time, not only the first. Tab reuse and the setup instruction interacted badly: the button asks for the library at `?openSetup=true`, the library read that flag once on mount and left it in the address bar, and the tab-reuse helper only navigates when the URL it is asked for differs from the one already open. So the second click found an identical URL, merely focused the tab, never remounted, and did nothing at all — verified against the built extension, where the click went from opening the sign-in window to opening nothing. The flag is now cleared the moment it is read, which also stops a plain page reload from re-opening the setup wizard by itself.

- Linking an existing empty repository now leaves you with the same repository that creating one does. Three steps run after the link: the initial file structure, the repository settings, and GitHub Pages. The create path ran all three as best-effort, recording a warning if one failed and carrying on. The link path ran the first two unguarded and skipped Pages entirely — so a hiccup in either aborted the link with an error, and even a clean run produced a repo with no Pages site, which meant `github_pages_url` stayed unset and every badge in the generated README pointed at a repository-relative path rather than the published report. The link path now runs the same three steps, in the same best-effort wrapper, and records the repository before them so a failure in an optional step can no longer strand a validated repository unlinked.

- Repository setup failures are visible instead of silent. The step that applies repository settings and topics issued both GitHub calls and discarded both responses without checking them, which made the surrounding warning machinery unreachable: a token without the right scope produced a repository with none of the settings applied and no topics, and the wizard still reported that step as done. Both responses are checked, and a failure now appears in the setup warnings with GitHub's own reason.

- The empty-repository check when linking accepts GitHub's 409 "Git Repository is empty" as well as 404. Only 404 was treated as empty, while the equivalent checks elsewhere in the extension already read 409 that way. Nothing changes for a repository that does have commits: the code that writes the first commit re-derives emptiness from its own branch lookup and still builds a normal child commit.

- Setup links stop stacking duplicate tabs. "Complete setup" appears three times in the library — collapsed sidebar, expanded sidebar, and the banner — and each click opened another welcome tab, so a user who clicked it twice ended up with two identical pages and no indication which one was live. Every opener now looks for a tab already showing that page, activates it and raises the window it lives in, and only creates a tab when there is genuinely none. Raising the window matters as much as activating the tab: a tab that goes active in a background window looks exactly like a button that did nothing. The links are still real anchors, so middle-click, "copy link address" and the hover URL preview keep working, and a Ctrl- or Shift-click still gets you the second tab you explicitly asked for. The same applies to the welcome page's own buttons, which open the library at four different sections — a run through the checklist used to leave four libraries open, and now re-points one.

- The welcome page's claim that it "can be reopened from the extension popup at any time" is true now. There was no such entry in the popup: the only way back was reinstalling the extension or typing the internal URL by hand. The popup footer has a **Setup guide** link.

- Committing into an empty GitHub repository works. A repository with no commits answers the git-data endpoints with `409 Git Repository is empty`, not `404` — the repository is there, the branch simply is not yet. The branch-resolution guard in the GitHub handler admitted only 404, so the 409 escaped `commit()` as a rejected promise and the root-commit path that exists for exactly this case was never entered: it was reachable only through 404 → create repository → 422 "name already exists", a sequence an empty repository never produces. Anyone who linked a repository that had never been committed to — the state every freshly created one is in — had every commit fail, permanently, for as long as it stayed empty. That is a first-run failure: it is what a new install on a new account hits before it has done anything else. The same 404-only guard in the poll that waits for a new repository's first commit gave up the moment GitHub served a 409 mid-warm-up; both statuses now read as "not ready" and the poll continues. Two other places in the extension had already recorded 409 as GitHub's answer for an empty repository — the repository health check and the onboarding modal — while the handler's own comment asserted the ref lookup "404s on those forever". The comment was wrong, and that wrong assumption is what shipped; it has been corrected alongside the code.

- The Firefox install links no longer 404. The README badge, the README download table, the landing page's browser badge and `EXTENSION_STORE_URLS.firefox` all pointed at `addons.mozilla.org/firefox/addon/codeledger`, which has never existed — there is no AMO listing. All four now point at the releases page and say what they are: a zip, not a store install. `EXTENSION_STORE_URLS.edge` had the same problem and is corrected the same way, with a comment at the constant saying to put the store URL back when a listing exists.

- `BUILD.md` can now be followed. AMO's source review reads that file to reproduce every generated file in the tree, and it named a command for `preact-bundle.js` and nothing for `chart-bundle.js`, which is the second-largest generated file shipped. The generator that was missing is now written (`dev/generate-chart-bundle.js`, wired as `npm run vendor:chart`), the bundle is regenerated from it so the committed file and the command agree, and the document carries a row per generated file with the command that reproduces it and whether it is minified. A generated file with no command behind it is the exact failure mode that review exists to catch.

- The generated ledger README no longer repeats itself. Three separate generators write into that one file, and each was only ever tested alone, so nobody saw what the reader saw: the total solve count appeared three times and the Easy/Medium/Hard split twice, from two different counters that do not always agree. The badge row's `solved` and `by difficulty` badges have been dropped from the defaults — the stats block directly above already carries those four numbers, for every user, whether gamification is on or not — and the four-column stats table that restated them a third time is gone, leaving the Stats section to the platform, language and topic breakdowns that are actually additional information. Both badges still render for anyone who ticks them.

- The streak card is centered with everything else. `upsertReadmeBlock` prepends its block when it cannot find its markers, and the README template never wrote any — so the card, the badge row and the achievements line landed at the very top of the file, above and outside the `<div align="center">`, left-aligned above the title. The template now emits the marker pair in place, inside the centered block and below the count badges.

- Two badges no longer share the label "solved". The `difficulty` badge was labelled `solved`, same as the `solved` badge, so a README showing both had two adjacent badges whose left half read the same word — wrong in the self-hosted SVG and in the shields endpoint JSON alike, since both read the label from the same spec.

- Nightly badge refreshes reach the published page. The card in the README is an `<img>` pointing at the Pages copy of `badges/card.svg`, but `badges/**` was missing from the deploy workflow's `paths:` filter, so the refresh rewrote the SVG, committed it, and never triggered a redeploy — the card kept showing whatever numbers were true the last time some _other_ file changed. The refresh workflow also checked only `badges` for changes while staging `badges README.md`, so a README-only change was staged and then discarded.

- The published stats page no longer serves zeros to everything that does not run JavaScript. The six counters were literal `0`s in the markup, filled in from `index.json` after load, so a browser saw the real numbers but `curl`, a search crawler, a link unfurl and anyone with scripting off saw a page claiming no problems solved — and, because the reveal is what un-hides the page, a reader without JavaScript sat on "Loading stats…" indefinitely. The generator already holds the counts at the moment it writes the file (it is the same `index.json` the README shields are built from, so the two cannot disagree), so Total, Easy, Medium and Hard are now baked into the markup and into both the `description` and `og:description`, and a `<noscript>` rule reveals the stats row while hiding the cards that only script can draw. The runtime render still overwrites all four, so nothing goes stale between refreshes. First-run onboarding still emits zeros, where zero is the true answer.

- Best Streak is baked into that markup as well; Current Streak is deliberately left as a placeholder. The two cells look alike and are not alike. A best streak can only change when a solve lands, and a solve is what triggers the refresh that rewrites the page — so the number is regenerated at the same moment it could go stale. A current streak decays on its own: a repository that goes quiet commits nothing, nothing regenerates the page, and a baked "12d" would go on telling crawlers and no-script readers that a streak is running days after it ended. "—" is not knowing, which is true; a stale number is a false claim. Deriving it needed one more fix — the meta handed to the generator carries only the ten most recent problems, which can describe at most ten days, so the streak is now computed from the full list before that slice and passed alongside the counts.

- The published stats page no longer hides itself while it fetches. `#app` shipped with `display:none` and was revealed only once `index.json` resolved, so a reader with JavaScript watched a half-viewport spinner sit on top of counts that were already in the markup. The stats row is now visible immediately and only the script-drawn cards — heatmap, charts, knowledge graph, commit list — wait for data, which is also what a failed fetch now leaves on screen instead of an error and nothing else.

- The published stats page declares a canonical URL and ships JSON-LD. Both were missing from a page that has a stable public address and is worth indexing. The address is the one GitHub reports for the site, which is where a custom domain is recorded — nothing else in the tree knows the site is served from one — and when Pages is off or has not been checked yet no canonical is emitted at all, because a guessed `{owner}.github.io/{repo}` would name the wrong host on every custom-domain site. The JSON-LD is a `WebPage` carrying the same description and attributing the page to the repository owner, escaped the same way the commit list is so a value containing a closing script tag cannot end the block.

- Tidied the README header: the "View Live Dashboard" link and the "Last updated" line ran together into one line because adjacent lines are one paragraph in markdown, and the empty string that stood in for the timestamp when absent left a blank line behind. The six count badges now share one shape — the `Solutions` badge was the only one carrying a logo — with `Languages` moved off the colour the points badge uses and `Platforms` off the grey that means "zero" on a gamification badge, which made it read as disabled.

- A sync payload that fails to build says so. Every commit bundles `.codeledger/sync.json` alongside the solution, and the two places that build it swallowed any error without a word. The solve still committed, which is why this was invisible — but the other devices then read a stale `sync.json` and nothing anywhere said why. The failure is now logged with its reason. The commit still goes through: a solve you cannot recover matters more than a sync payload you can rebuild.

- Every NeetCode and takeuforward link on a published Pages report pointed at a file that was never committed. The report rebuilds each file's path from `index.json` rather than storing it, and its copy of the platform-code table listed three of the five platforms. The two missing ones fell through to the first three letters of their name, so the links read `problems/nee-…` and `problems/tak-…` while the solutions sit at `nc-…` and `tuf-…`. The table is now read from the same constant the writer uses, so a sixth platform cannot be left out of it again.

- The same links dropped the sanitisation the writer applies. A slug is scrubbed on its way into the repository — separators, dot-segments and anything outside `A-Za-z0-9._-` — and the report was rebuilding paths from the unscrubbed value, so any problem whose slug carried one of those characters linked nowhere. The scrubbing now happens on both sides, and the tests pull the report's own copy back out of the generated page and run it against the real one, so the two cannot drift apart again.

- Layout migration no longer orphans the files of a problem with a canonical match. It asks which paths a problem already occupies, and built that question from the raw canonical ID while every file had been written under the scrubbed form of it. Where the two differed the answer was "no files", so the old copies were left behind instead of being moved.

- The library refreshes itself after a solve again. The service worker announces a saved solve to every open library tab, and it looked those tabs up by the exact URL `library/library.html`. A match pattern's path is compared against the path _and_ the query string, and every route that opens the library appends one — the popup's three entry points, the welcome page, the floating panel, a problem card, the importer, the injected button and the worker's own tab opener. So the announcement reached no tab at all, and the library only picked up a new solve when you reloaded it by hand. Fixed by matching `library.html*`, which is the same rule `browser-compat.js` already documents for the tab it focuses.

### Security

- A custom AI endpoint can no longer arrive from anywhere but you. The AI provider settings include an optional base URL, so you can point a provider at Azure OpenAI, a LiteLLM instance or your own gateway. That URL decides where your solution is posted and where your API key is sent in the Authorization header — and settings arrive from two places that are not you: `sync.json` in your ledger repository, and a restored backup file. The portability rule that decides which settings travel waved `openai_endpoint` through on the strength of its `openai_` prefix, in both directions, so anyone able to write to that repository (a collaborator, or anyone holding a leaked token) or able to hand you a backup file could redirect every later AI review and every model-list refresh to a server of their choosing, along with the key. Endpoint overrides are now local-only: never written to the repository, never accepted from it, never carried in a backup. They remain fully configurable in Settings → AI, which is the only place they were ever meant to come from.

- The knowledge graph's tooltip in the published Pages report escapes the platform names it shows. Everything the tooltip draws comes from `index.json`, which is repository content — on a public repo, or one where a token has leaked, whoever can land a commit chooses those strings, and the report is served from your own `github.io` origin to whoever you have shared it with. The problem title beside them was escaped from the start, which is what made the gap easy to miss. Nothing else in the report was affected; the graph section is new in this release and the remaining thirteen interpolation sites were already covered.

- Code recovery now checks which tab answered it. When the extension re-fetches the code for a solve it already knows about, it opens a background tab and waits for that tab's content script to report back — and the reply was matched only on the problem id. That id travels in the recovery URL's query string, so it is not a secret: any page on LeetCode or GeeksForGeeks could be sent a link that makes it produce a matching reply, and the reply is saved over the stored solution and queued for commit to your repository. The reply must now come from the tab the extension itself opened, which is the part of the message a page cannot choose.

- Debug logging no longer prints any part of a credential. Storing the GitHub OAuth token logged its first twenty characters — the `gho_` marker plus sixteen characters of the token — and the AI key pool logged the first eight of whichever key it was cooling down. Both lines existed to confirm a value had arrived, which neither needs the value to do; they now report the length and the provider. The key pool's eight characters were mostly the vendor's own marker and disclosed close to nothing, but debug output is something people paste into bug reports and screenshot into issue threads, and a token prefix confirms to a reader that the rest is real.

- The OAuth callback page is served under a content security policy. It is the one response that hands your freshly minted, repo-scoped GitHub token to the extension through the DOM, and it had no CSP, no framing rule and no MIME-sniffing rule at all. The policy is `default-src 'none'` with no `connect-src`, so a script that somehow ran on that page would have nowhere to send the token; the inline style and script carry a nonce minted per response, since a static hash cannot work on a script whose contents include the token. `frame-ancestors 'none'`, `X-Frame-Options: DENY` and `nosniff` come with it. No behaviour changes — the same page, the same payload, the same `data-auth` handoff.

- The network tap's reach is now locked by a test, and its limit is written down. NeetCode and takeuforward render their verdict out of a JSON response no isolated-world script can read, so one content script runs in the page's own world to wrap `fetch` and `XMLHttpRequest` on those two hosts. Sharing a world means sharing a message channel: a compromised page on either host can post a well-formed "accepted submission" and have code of its choosing committed to your repository. That is **not fixed and cannot be fixed with a shared secret** — both halves would have to agree one over `window`, where every listener hears it, and the isolated half runs after the page's own scripts, so no handshake would ever be private. A nonce there would look like a defence and be none, and it is written down as an unfixed residual risk in [docs/THREAT_MODEL.md](THREAT_MODEL.md) rather than papered over. What holds is the scope, so the scope is now a test: one main-world script, those two hosts, top frame only, endpoint allow-list checked before anything is read, no header access, no wildcard target origin. Widening any of those is a one-line change in a file nobody reads closely, which is exactly why it is now a test that fails. Content scripts share the page's DOM, so the page can find our buttons and call `.click()` on them; the import and sync buttons read the current solution and commit it, so a compromised or XSS'd platform page could drive commits you never asked for, repeatedly, with nothing on screen to show for it. The ten buttons that write to your repository now require a real click. This deliberately does not cover the copy, paste and AI-panel buttons, which write nothing, or the listeners attached to the platforms' own submit buttons, where a site clicking its own button is a normal thing to do and refusing it would break real submissions.

- Records arriving from `index.json` no longer get to set the extension's own bookkeeping fields. Sync reads that file back out of your ledger repository, and it stored what it found there verbatim — including the two underscore-prefixed fields the extension keeps for itself. `_committedPaths` is the list of files a problem last wrote, and the maintenance pass deletes every path in it the problem no longer writes: a record naming `.github/workflows/release.yml`, or any other file, would have had it deleted from your repository on the next Resync All. `_conflictResolvedAt` dated far enough ahead stops a problem from ever raising a conflict again, so one record could be kept from review indefinitely. Both are now dropped on the way in, by namespace rather than by name, so a field added later is covered too; committed paths are re-derived from the actual repository tree, which is the truth the stored copy was only ever a cache of. Only the incoming side is stripped — your own device's copies of those fields are what a resolved conflict is remembered by. A malformed entry in that file is also skipped now instead of aborting the whole import on the first one.

- A remote solve can no longer replace a local one without asking. Sync matched records on problem-plus-language, but the library stores one row per problem, so a record with the same problem in a different language was classified as new work — and then merged straight over the local solve when it was saved, code and all, with no prompt and nothing to undo. It is now treated as what it is: two records wanting the same slot, which is a conflict for you to settle. To be plain about what this is not — the two languages still cannot be kept side by side, because one problem is one row; that would be a change to how solves are stored, not to how they are synced.

- Every AI request now validates its endpoint at the point of use as well. A URL that is not `https:` — or `http:` on loopback, which is Ollama's shipped default — is dropped and the built-in endpoint used instead, so a value from an older profile cannot downgrade the connection your key travels over. To be plain about the limit: this checks the scheme, not the host. Any `https:` URL you can be persuaded to type into the endpoint box will still be used, because a host allow-list narrow enough to mean anything would break the custom-gateway feature it was guarding. Keeping a hostile URL out of your settings is what the change above is for; this is the backstop.

### Removed

- Two pieces of code that could only ever do harm if they ran. `getActionsWorkflow()` generated a `.github/workflows/update-stats.yml` for your ledger repository — a nightly Action that rewrites the README, which is a file CodeLedger already rewrites on every commit; the infrastructure builder has deleted that exact path whenever it finds one for several releases, so the generator was writing something its neighbour was there to remove. Nothing called it. `dev/vendor-downloader.js` fetched Preact and htm from a CDN into `src/vendor/`, over the top of the files that are copied there from npm and carry their source path in a header comment. Nothing called that either, and running it would have replaced a reviewable provenance trail with an opaque download and quietly downgraded Preact by three minor versions.

## [1.8.1] — 2026-08-19

### Added

- The Solutions tab now answers "what should I solve next", not just "what have I solved". An **Up next** bar suggests up to three problems, ranked from data the library already holds and computed without any network call or AI: the unsolved similar problems LeetCode attaches to your most recent solves (a candidate named by several recent solves outranks a one-off, and each card says which solve it follows and when), problems serving your active roadmap milestone, which outrank the merely recent, and — when the similars run dry — your least-practised topic as a "revisit" nudge. A reroll button pages through the rest when more than three qualify.

- Solving on vacation now counts. A vacation day was strictly neutral — the streak survived, but a day you chose to solve anyway earned nothing, which made ending a break early strictly worse than sitting it out. A vacation day that reaches the daily target now extends the streak and banks freezes exactly like any other day, so coming back early always pays; a partial vacation day stays neutral rather than turning into a miss. Two achievements land with it: **Back In Action** (hit the target while on vacation) and **Weekend Warrior** (solve on ten weekend days).

- Breaks are detected after the fact, not just declared in advance. Life happens without a vacation being declared first, and until now the only repair for a week away was rebuilding the streak from zero. When three or more consecutive zero-point days end yesterday — today is still in progress, and declared vacations don't count into the run — the Solutions tab offers to mark the run as a break with one click, which makes those days neutral and lets the streak pick up where it left off. The threshold is deliberately not configurable: below three days, freezes and the penalty buy-back are the intended tools, and a tunable threshold would let every single missed day be auto-forgiven. Someone with no solve history is never offered a break — you cannot be away from nothing.

- The extension's welcome page now mentions the desktop app. The landing page has been installable as a PWA since 1.8.0, but the only way to learn that was to visit the site and notice the button; the onboarding checklist now has a card pointing there, and says honestly that the install control lives in the site's corner once it detects the extension — the welcome page cannot install it for you.

- The AI review prompts are now editable. - A master switch for AI, offered only once it means something. Settings → AI now has an "AI features" toggle that hides every AI surface — reviews, chats, prompts — without deleting the provider keys underneath. It appears only after at least one provider is configured, because with nothing configured there is nothing to switch off and a dead toggle reads as a broken feature.

- Incognito mode has a control. The engine has honoured an incognito flag since it shipped — solves discarded instead of recorded or committed, with a banner while it lasts — but nothing in the UI could set it. Settings → Advanced now offers it with 1-hour, 4-hour, 24-hour and until-turned-off durations.

- The popup's recent solves are links now. Each one opens the library with that problem's dialog already open, instead of leaving you to find it again in the list.

### Fixed

- Navigating between problems with the dialog's arrow keys no longer strands the new problem in the old one's loading state. "Refresh problem data", "Generate AI review" and the code-recovery button each set a busy flag that only their own completion cleared — arrive at a different problem mid-flight and it inherited the spinner, and worse, the stale completion then wrote the _old_ problem's update over the dialog, snapping it back to the problem you had just left. Every async completion now checks it still belongs to the problem on screen before touching anything, and switching problems resets all transient state.

- The commit message template is honoured. Settings has offered a `commitMessageTemplate` with `{topic}`, `{title}`, `{difficulty}`, `{language}` and `{platform}` variables for as long as the setting has existed, and nothing ever read it — every solve commit used the built-in format regardless of what was typed. The Platforms panel lets each platform declare what it calls Easy, Medium and Hard — GeeksForGeeks' "School" and "Basic", for instance — but only the global mapping was ever consulted, so aliased solves fell through to a guess in stats and badges. The per-platform maps are now folded into normalization, with the explicit global mapping still winning on conflict.

- Problems from Codeforces, NeetCode and takeuforward no longer open the dialog onto "No content." The dialog hardcoded an "overview" first tab that only LeetCode and GeeksForGeeks problems actually have; it now opens on the first tab the problem really offers.

- The privacy panel no longer offers a jump button that goes nowhere. The mermaid disclosure's "review setting" button pointed at a settings panel with no mermaid control on it — per-diagram rendering is decided on the diagram. The button is gone; the disclosure text remains.

### Removed

The library's hand-written settings panels replaced the schema-driven settings renderer some releases ago, but the old machinery stayed in the tree, unreachable but still shipping: `SettingsView.js`, the 2,000-line `SettingsSchema.js`, `DifficultyMapPanel.js`, `MirrorsPanel.js`, the registry's `getAllSettingsSchemas()` that only they called, and `src/sidebar/sidebar.html`, which no manifest has pointed at since the sidebar became the library page. ## [1.8.0] — 2026-08-19

### Added

- Commits that keep failing are now visible without opening DevTools. Every solve was already saved locally and quietly retried every ten minutes, but nothing on screen said so — a broken token or an offline week looked identical to everything working. Now, when a solve has been stuck uncommitted for longer than the automatic-retry window, the toolbar icon shows a red `!` whose tooltip counts the stuck solves, and the library shows a banner with the same count and a "Retry now" button wired to the existing bulk resync. Both clear themselves within one retry cycle of the commit landing. A commit merely in flight, or one the next ten-minute retry has not reached yet, shows nothing — the warning is for stuck, not busy. The banner, and a matching chip in the popup, also state when the next automatic retry fires and count down to it, refreshed every fifteen seconds — "it will retry" was unfalsifiable, "retrying in 4 m" is a claim you can watch come true.

- Vacations can now be declared, not just honoured. The streak engine has understood vacation ranges since it shipped — days inside one neither break nor extend a streak, and an ice-breaker ramp eases the daily target back in afterwards — but the only way to declare one was writing JSON into storage by hand, so in practice nobody could. Settings → Streaks gained a Vacations card: add a range with a start date, an optional end (leave it open for "until further notice"), and a note; current and upcoming vacations are listed with their state and can be removed. The same panel now also narrates your configuration back to you as one live sentence — what your daily target is, what a freeze costs to earn and a miss costs to repair, with the engine's clamps applied — so what you typed and what the engine will actually do are visibly the same thing.

- The library can be installed as a desktop app. The landing page is now a PWA — a service worker caches the static shell (never anything under `/api/`, so OAuth and health checks always hit the network), and an **Install desktop app** button appears in the hero when two things are both true: the browser offered an install prompt and the extension's handshake proved an install. The gating is the point — the installed window is the landing page, and its whole value is the "Open Library" relay into the extension, so offering it to someone without the extension would install a brochure.

- More analytics, in the library and in the published report, shaped so an AI can read them. The Analytics tab gained a solving punch card (day-of-week × hour-of-day, with your peak hour named), a stacked twelve-month difficulty progression showing whether the mix is shifting from Easy toward Medium and Hard, and median solve time per difficulty from the floating timer's recordings — medians, because one tab left open overnight would wreck a mean. Above them all sits an **AI-Ready Insights Export** card: one button copies a single JSON object — totals, streaks, activity rhythms, monthly difficulty mix, platforms, languages, top topics, solve times, no problem titles and no code — to paste into any AI chat and ask what to practice next. The GitHub Pages report renders the same punch card and progression chart and embeds the same JSON in the page (`window.CL_INSIGHTS`, and a `#cl-insights` element), so a prompt written against one export works against the other.

- The Solutions page opens with the numbers that used to require a trip to Analytics: a compact strip across the top with the current streak, best streak, solves this week and total — the page people actually land on now answers "how am I doing" before "what did I solve".

- Two more ready-made roadmaps, following the study orders NeetCode and takeuforward publish themselves — **NeetCode roadmap order** and **Striver A2Z order**. Someone working through either sheet already has that sequence in their head, and a roadmap that disagrees with it is one more thing to reconcile. What these reproduce is the topic order, not the curated problem lists: a milestone is satisfied by any solve tagged for that topic, on any platform, which is also the more useful behaviour given both sheets send you elsewhere to actually solve. They are named and described so as not to suggest the lists themselves are being tracked.

- Imported Codeforces problems now fill in their own statements. An import reads every accepted submission from `user.status`, which states the title, the tags and the rating but has no room for the problem text — so a back catalogue of hundreds arrived with hundreds of empty README sections, and the background repair pass skipped them all because Codeforces publishes no statement API. It has no API, but it does serve the problem page, at an address CodeLedger already builds from the same slug it stores. The repair pass now reads that page: a plain public GET the extension makes itself, no tab opened, nothing on screen, and deliberately signed out so the request is not made as you. The statement it lifts is the same fragment the extension captures when you solve one live, so a healed problem and a solved one read identically. Tags come from the same page, which closes the other gap for the handful of problems the API tags with nothing. A page that comes back truncated, or as one of Codeforces' challenge interstitials, yields nothing rather than half a statement, and is retried on the same widening schedule as everything else.

- CodeLedger now works out for itself whether you have TUF+, instead of leaving takeuforward's card silent about why nothing is being committed. There is no endpoint that answers "is this account a subscriber", and the GitHub account you sign in with cannot say — it is a different identity on a different site. But takeuforward's own problem endpoint answers to anyone and replaces difficulty and tags with the literal text "Subscribe to TUF+" when the request is not a subscriber's, and CodeLedger already reads that response for its metadata. Opening any TUF+ problem page is therefore enough to settle it, with no extra request, endpoint or permission. The platform card then says which side of the paywall you are on, and states only what that response proves: with a subscription, that problems arrive carrying their difficulty and topic tags; without one, that sheet mark-up is unaffected, but anything committed from takeuforward arrives without either, because the site withholds them. Whether takeuforward's judge itself runs for a free account is not something the extension can determine, so the card does not say. Nothing is switched off on your behalf either — a toggle turned off automatically stays off after you subscribe.

- A broken import can now be fixed by hand — on every platform, not just GeeksForGeeks. The verification sweep repairs what it can by trying the known slug generations, but when every variant is gone the automatic options are exhausted — while the user may know perfectly well where the problem lives, having just found it with the site's own search. Each row in the broken-links dialog therefore gained a **Fix link** button: paste the problem's URL (or bare slug) and it is checked against the platform before anything is saved, so a manual fix can never replace one broken link with another. Each platform is asked in the way it can actually answer: LeetCode through the same GraphQL endpoint the extension already reads, GeeksForGeeks through its practice API, NeetCode through its public metadata endpoint, and Codeforces by membership in the full problemset listing its API publishes. Two cases genuinely cannot be checked from the extension, and are saved honestly unverified rather than silently or falsely stamped: takeuforward's backend refuses requests from any origin but its own site, and Codeforces gym problems are absent from the problemset listing by design. In both, the pasted link is still strictly parsed against the platform's URL shape — a LeetCode URL pasted into a takeuforward record is rejected, not mined for a slug — and the row says plainly that the save is unverified and the link should be opened to confirm. A confirmed fix behaves exactly like an automatic repair — only the link changes, the record's identity and any files already committed stay put, and the corrected record is queued for the next sync. A network failure during any of these checks blocks the save without condemning the input; only the platform's own definitive "no such problem" does that.

- The Edit tab in the problem dialog now edits everything, not just title, difficulty and tags. Every field a record carries is on the form: the problem link (paste a full URL and the slug is extracted, with a live preview of where it will open), the solve date and time, time spent, language and the file extension that names the committed file, runtime, memory and their percentiles, acceptance rate, the solution code itself and the problem statement — plus the notes that were already there. What used to be a read-only metadata grid is now the input form; the only fixed field is the record's id, which keys the file's path in the repository and is shown but not editable. The link field also gained a **Check link** button that asks the platform whether the slug resolves before you commit to it — the same per-platform checks the broken-links dialog uses, including the honest "can't be auto-checked" answer for takeuforward and Codeforces gym. Saves land locally and queue the record for the next GitHub sync, exactly as the smaller form did.

Clicking it captures the page the same way the manual "Sync to Ledger" button does (editor code, title, difficulty, tags, statement) and commits it; if the editor holds no code, the button says so and points at the Submissions tab, whose per-row Sync buttons recover the real submission.

- Topic proficiency now fades with neglect, at a rate you choose. The mastery colouring — the graph's hub bands and the Topic Gaps ranking — used to read a topic solved once, years ago, the same as one exercised last week, because it only asked _whether_ a topic had solves, never _when_. Proficiency now decays from the last time a topic was meaningfully touched, with a configurable half-life (default 90 days), and "touched" is stricter than "solved once": recency is measured from the Nth-most-recent solve, so a single drive-by problem does not repaint a rusty topic as fresh — it takes the configured number of solves (default 2) to genuinely regain it. Both knobs live in Settings → Platforms under **Topic Proficiency Decay** (half-life 7–3650 days, regain solves 1–8); a blank or missing value falls back to the default rather than to zero, so clearing a field can never freeze or erase the decay.

A `/graph` chat command inserts a digest of it into any chat — the totals, every topic on each axis with its solve count, mastery band and recency, the topics that have decayed since they were last practiced, and the unsolved suggestions the graph links to current work — and the digest states the decay model's configured numbers, so the model reasons from the same rules the colours use. The digest also arrives on its own: when a question is the kind the graph answers — what to practice next, where you're weak or rusty, how you're doing — it is attached as context automatically, without rewriting the message, and the recognition is deliberately narrow so a chat about one problem ("suggest a better approach for this problem") never drags the whole graph in. Both paths run in the background worker, so they work identically from the library chat, the floating chat and the problem modal — the floating surfaces used to expand `/graph` to "not available here". The graph page itself gained an **Ask AI about this graph** button (present only when an AI provider is enabled) that opens the chat tab with a prompt pre-filled around the command. The digest is built on demand from the same graph the page renders, so what the model sees is what the screen shows.

- The Party tab now looks like a competition instead of a table. The top three ledgers stand on a podium with medals (the medals carry into the list ranks), a leaders strip crowns whoever holds each metric — points, both streaks, solves, level — and every friend's row states its gap to you as a signed chip, so the standings read at a glance instead of asking for mental arithmetic. Opening a friend now starts with a head-to-head duel: your numbers against theirs on every metric, winners coloured, and when you trail on points, how many days of hitting your own daily target would close the gap — your target, deliberately, because their pace is not something their stats file states and inventing a number for the most motivating line on the page would poison it. Below that, an achievements duel splits what they hold and you don't (and the reverse) with the proper emoji and names — ids from a newer CodeLedger than yours show as-is rather than being hidden — and the deep-dive gained a 30-day activity strip drawn with its gaps, because the gaps are the story. Everything still reads only the public files each person's own extension commits; nothing about the tab's no-server, one-sided, self-reported nature changed, and the new comparison logic lives in the same shared module the landing page's /compare route uses.

- Which achievements the README showcases is now yours to choose. Every earned achievement was written under the badge row unconditionally — including the pair that reveal you run AI review, which is nobody's business but yours. Settings → Gamification gained an "Achievements to showcase" card listing every achievement the ledger can currently show, each with a checkbox; untick one and it stays out of the README while remaining earned everywhere else. The default remains "everything earned", and stays live — an achievement earned later showcases itself without a return trip to the panel — but an explicit selection is honoured exactly, including unticking them all, which removes the line entirely. The selection travels with the rest of the portable settings, and the nightly refresh workflow reproduces it identically, so the Action can never resurrect a line the extension was told to drop.

- **NeetCode** and **takeuforward (Striver)** are now tracked platforms. Both are single-page apps that send your submission to a judge over `fetch` and render the verdict into a React tree that is gone the moment you navigate — there is no "Accepted" node that survives long enough for the DOM watchers every other handler uses. Their handlers therefore read the judge's own response, through a small script that runs in the page's world and mirrors only those two sites' judge endpoints back to the extension. Nothing else is mirrored, and the script runs on those two hosts and nowhere else.
- On takeuforward, the parts that do not need a subscription work without one. takeuforward's own editor is part of TUF+, and the free A2Z, SDE and 79-problem sheets link out to other sites rather than offering one — so the sheets are where a free account spends its time, and they are public. CodeLedger now marks the rows you have already solved, including rows you solved on LeetCode or NeetCode rather than on takeuforward itself. Problem metadata comes from takeuforward's public endpoint, which replaces difficulty, tags, hints and editorial with the literal text "Subscribe to TUF+" for non-subscribers; that sentinel is stripped rather than committed, so a problem is recorded with no difficulty instead of one whose difficulty reads as an advert.

The behaviour bank has recorded solve times, resubmits, hint views and what reviews flagged since it shipped, but nothing ever read more than one problem back at a time — so the review of your fourth off-by-one bug knew nothing about the first three, and the library chat started from zero every session. Reviews, all three chat surfaces and the solution merger now receive which review flags recur across separate problems, which topics you needed help on, your median pace per difficulty, and your hint and resubmit rates. A flag has to appear on two different problems to count, unstarted timers are not read as fast solves, and below five recorded problems nothing is claimed at all.
- A **Behaviour** tab in the library's Behaviour Bank page — which until now showed insights, roadmap and skills, none of which is the behaviour bank. It shows the derived profile, the exact prompt text the model receives, and the raw per-problem records. Anything shaping the model's answers should be something you can read, and clear.
- Incomplete problems now repair themselves in the background. A solve can arrive without its description or its tags for reasons that have nothing to do with you — a profile import knows the slug and nothing else, a submission page renders the verdict before the tags load, a request times out — and until now the fix only happened if you found the button, pressed it, and sat there with the window open. A background sweep now takes a couple of incomplete problems every few minutes and asks LeetCode or GeeksForGeeks for what is missing, over plain HTTPS, with no tab opened and nothing on screen. It only ever fills gaps, so nothing you have written can be undone by it; a problem that fails backs off on a widening schedule and is left alone after five tries, because some problems genuinely have no description to fetch and retrying those forever is just traffic. Codeforces is excluded deliberately — it has no description endpoint, and the only alternative is opening the page behind your back. Off with one switch in Settings → Advanced.
- One **Refresh problem data** button in place of the separate "Fetch Description" and "Recover Code" buttons, which each repaired one part of a problem and left you to notice the other. It fetches the description, the tags and the missing code in a single press.
- The Insights tab now fills itself. It has always said the AI would add insights as you chat and solve, and nothing ever did — the only two things that could write one were a form you had to find and a tool the model was never told to use, so 283 recorded problems still read "0 insights stored", which looks broken rather than empty. CodeLedger now writes its own from your solve history: what your reviews keep flagging, and which topics have needed a second pass. A pattern has to have repeated across at least three separate problems before anything is written, and each one names the problems it was drawn from, so the claim is checkable instead of being a number you have to take on faith. These recompute themselves, so they correct as you improve and disappear when the pattern does; they are not sent to the model, which already receives the same statistics in a denser form.
- Ready-made roadmaps, so the Roadmap tab is usable without an AI provider. The only way in was to describe a goal and wait for a model to write a plan, which fails outright with no provider configured and asks everyone else to know what they want before they have a plan to react to. There are now four to pick from — Foundations, Interview core, Dynamic programming, Contest readiness — plus one built from your own history out of the topics that have actually cost you time. Any of them can be edited or replaced with an AI-generated plan afterwards.

The target of a mapping was a dropdown of the forty-odd built-in topics, so a tag that belongs to something the list has never heard of — a contest series, a company set, a technique nobody has agreed a name for — could only be filed under an approximation. Codeforces was the platform where a back catalogue could only be rebuilt by solving everything again: the extension had recorded, in its own source, that the API was unreachable from a content script, and nothing had rechecked it — `user.status` answers with `Access-Control-Allow-Origin: *`, and has for years. - The landing page now notices when the extension is installed and turns every install button into an **Open Library** control. Detection is a handshake with the extension's own content script rather than a check against a store extension ID, so a side-loaded developer build is detected exactly as a store install is. A click asks the extension's background to open the library tab, because a web page cannot navigate to an extension URL itself; middle-click and ctrl-click still work as ordinary links, since `library/library.html` is now web-accessible — to the landing page's origin and nowhere else.
- A problem summary on the three platforms that never had one. Codeforces, NeetCode and takeuforward have no endpoint that returns a problem statement, so their problems committed with an empty **Problem Statement** section that nothing in the extension could ever fill — the file recorded your solution to a problem it could not name. The AI review has your code and the title in front of it and can say what the problem asks, so it now does. It is asked only when no statement was recorded, so a real one is never at risk; it is stored in its own field rather than in the statement's, and it is committed under a **Problem Summary** heading that says the AI reviewer wrote it — a paraphrase filed under "Problem Statement" in a public repository would read as the platform's own words. A model that cannot tell what the problem asks was told to say nothing, and an answer that is a refusal, an apology or a single clause is dropped rather than committed, because an absent section makes no claim and a bad one does.

### Changed

- The Behaviour Bank lives in one place now. Its data-management controls sat in Settings while everything they managed sat in the Behaviour Bank tab, so acting on what you were reading meant a trip across the app. The Settings panel is gone; the export, import and clear controls moved into the Backups panel as a fifth **Bank** tab, next to the other things you back up, and the Behaviour Bank tab keeps the reading.

- Settings pages stopped wasting the screen. Party, Behaviour Bank and the Privacy panel each capped their own width and centred themselves, leaving huge dead margins on anything wider than a laptop; the caps are removed and they fill the space like every other tab.

- The extension icon is the transparent-background mark with the white outline, regenerated at every size (16–128), so it no longer sits in a coloured tile on the toolbar; and the popup swaps to the light-mode wordmark when the popup itself is dark, instead of showing a dark logo on a dark card.

- The AI-review queue notice in the Solutions view is a designed banner rather than a bare "22 queued · 5 failed" string — counts split into labelled chips, a retry control on the failures, and it only appears when there is something in the queue to talk about.

- Data structures and algorithms are kept apart everywhere topics appear, instead of only in the one analytics ranking that already knew the difference. The two axes measure different things — a data-structure tag like Array is on almost every problem because it names the container, while an algorithm tag like Binary Search names the technique the problem was actually about — so any flat list mixing them is dominated by the containers and says nothing. The taxonomy that classifies every canonical topic (with your own overrides from Settings → Platforms) already existed; it now drives every surface. The Topic Depth radar reads one axis at a time behind an Algo/DS toggle and scales depth within that axis, so Array's count no longer sets the 100% mark that flattened every algorithm into the centre of the chart. The Solutions tag filter groups its dropdown by axis, in canonical names. Topic chips on problem cards and in the problem dialog sort algorithms first and tint the two axes apart (cyan for algorithms, amber for structures) so the technique leads and the container trails. And on the knowledge graph, the axis is part of the picture itself: algorithm hubs stay discs, data-structure hubs are diamonds, domain topics (SQL, Shell) hexagons; the sidebar legend and the topic filter are grouped under the same headings, and each heading carries a hide-all chip that hides or restores that whole axis at once while clicking the heading itself zooms the camera to it.

- The knowledge graph was rebuilt on a real graph engine. The old page ran a hand-written physics simulation that let nodes drift into each other and buried its answers under four layout modes, compare dropdowns and a depth slider — a control for every question instead of a picture that answers them. The new page renders through vis-network (vendored into `src/vendor/` as a committed esbuild bundle from the official npm release, like Preact and Chart.js — nothing is fetched at runtime), whose layout keeps nodes clear of each other and then freezes, so the map holds still and the same library lands in the same shape every time the tab opens. What remains is one picture and one sidebar: search that flies the camera to any problem or topic (revealing it first if a filter was hiding it), a topic sidebar where clicking a row flies the camera to that cluster and an always-visible chip on the row hides it or brings it back, an inspector showing a node's connections and — for a problem solved on more than one platform — every canonical version with a link to each site, and the difficulty, platform and topic filters. Solved-only is now the default view; unsolved suggestions appear as small dashed ghosts only when asked for. Zooming carries the levels by itself: topic names read from across the room, problem titles resolve as you approach. The colour-by-mastery mode behaves as before. The full details view now opens the same problem modal the Solutions list uses — one modal per node, its "also solved as" chips flipping between the canonical versions — instead of stacking one modal per version with the close button hidden, which left the graph's copy of the dialog impossible to dismiss. The sidebar keeps one width — 280 pixels, always — with anything long scrolling inside it, because a panel that resizes itself on every click is the most distracting element on the page. Its inspector asks one question per list: a topic's card lists that topic's problems, a problem's card lists what it connects to — previously a topic showed both sections saying the same thing twice — and each list scrolls instead of compressing. The taxonomy's axis filter is on this page too, as a segmented All / Algo / DS / Other control beside difficulty and platform. Selecting a node brightens and thickens its edges so its connections stand out from the rest of the wiring. The colour strip in the corner expands into a full vertical legend — every shape, ring, colour band, edge style and ghost explained, stating the decay numbers the mastery colours are actually using, scrollable, collapsing back to the strip, its open state kept in the URL like everything else — instead of assuming the encoding is self-evident. The whole view lives in the URL: every filter, the hidden clusters and the selected node are query parameters, so a reload lands exactly where you left off — selection included — and the problem dialog's graph button deep-links to its node with the camera flying to it, rather than merely opening the tab. And filtering re-settles what survives when it changes enough to matter: hiding an axis or a large cluster reheats the layout so the remaining nodes regroup around the centre, while hiding and restoring a small group leaves the map exactly where it was — repeatedly toggling a one-problem cluster used to slowly rotate the entire layout — and the camera stays where you put it instead of springing back to the full view after a zoom.

- The report page's calendar heatmap now spans the full content width, like every other card on the page. It used to share a row with the other charts, which squeezed a year of daily activity into a strip too small to read; those charts move into their own row, difficulty split first.

- The achievements shelf moved below the numbers, and its locked tiles fold away. It sat between the stat cards and the platform breakdown, where eighteen always-expanded tiles — most of them grey placeholders — pushed the actual analytics below the fold on the page people open to read them. The shelf now sits after the calendar heatmap, and locked achievements collapse behind a "Show locked" toggle once anything is earned; a fresh ledger with nothing earned still starts with them open, because the locked list is then the whole point of the shelf.

- **Codeforces is beta rather than alpha**, and is tracked by default like every other platform. The three faults that kept it in alpha are fixed — see Fixed below — and its card carries the same badge NeetCode and takeuforward do. It is not called stable because none of it has yet been confirmed against a live contest judge; the flow is covered by unit tests, which is not the same claim.
- AI reviews now record what they rewrote. A review has always been allowed to replace a problem's tags, topic, pattern and difficulty, and it did so leaving no trace — so a learner reading their own difficulty breakdown had no way to tell a value the platform stated from one a model decided on, and the chart looked equally authoritative either way. Each review now memos the fields it actually changed to the behaviour bank. Only genuine changes are recorded: the reviewer emits every field whether or not it is changing anything, so the record comes from comparing before against after rather than from taking the block at its word.
- The Gemini and OpenAI key fields no longer promise "rate-limit pooling". Both providers count quota per project — Google says so outright, "rate limits are applied per project, not per API key" — so a second key minted in the same Google Cloud project or OpenAI project shares the same limit and adds nothing. The fields now say that, and say that only separate projects add capacity. Rotation across keys still works and is still worth having; what was wrong was the claim about what it buys you.

- Fetching a description or recovering code no longer requires the problem window to stay open. Both used to run inside the window that asked for them — the code path polled storage for thirty seconds and then reported "Refresh timeout", whether or not anything had failed, and closing the window abandoned the work. The service worker now owns the whole operation, saves the result whether or not anything is watching, and tells any open window when it lands. Close it, come back, the data is there.
- The assistant can now see the roadmap you are working through, and ties its suggestions to it. Every chat receives the active roadmap's goal, which milestone you are on and how far into it you are, with an explicit instruction not to redirect you when you ask about something else.
- The six built-in skills were rewritten. They were one-line instructions — "ask questions instead of giving answers", "give incremental hints" — which is a label for a teaching style rather than a description of how to do it, and the answers showed it. Each is now a specific procedure: the Socratic mode asks one question at a time aimed at the gap visible in your code and gives up on a question after three wrong answers rather than repeating itself; the hint giver climbs a fixed five-rung ladder and never skips or repeats a rung; the reviewer must cite the line or give the input for every claim it makes.
- AI reviews now name what they flagged in their metadata block instead of leaving it to a keyword scan that recognised seven fixed phrases. A review that flagged an unnecessary sort or a mutated input used to write nothing back to the behaviour bank; now it does. The keyword scan remains as a fallback for models that drop the block.
- Roughly 140 unused imports, variables and functions were removed across some seventy files, following a CodeQL quality scan. Most were harmless leftovers, but not all of it was cosmetic: two were writes to state nothing ever read — the floating panel's copy-prompt position was tracked and never used, and a resync path destructured a token it never touched — and dead code of that shape is where the next real bug hides, because it reads as if it matters. The scan's five "useless conditional" and one "superfluous argument" findings are not enumerable outside GitHub's quality-scan UI and are not addressed here.

### Fixed

- The popup's streak bar said "Lv" with no number after it. The level lookup returns an object — `{ level, name, … }` — and the popup rendered the object where the number belonged, which stringifies to nothing useful; it now reads the `level` field, and falls back to 1 rather than blank while the snapshot loads.

- Degenerate gamification settings can no longer break the streak engine's arithmetic. A daily target of 0 made every day trivially complete; a freeze-earn multiplier of 0 or 1 banked a free streak freeze every single day, defeating the cap; a penalty multiplier below 1 made a missed day cost less than a normal day, so breaking a streak was cheaper than keeping it. The engine now clamps: target at least 1, both multipliers at least 1, and non-finite values fall back to defaults — and the Settings panel's live sentence narrates the clamped values, so typing 0 shows you what the engine will actually do instead of silently doing something else.

- The knowledge graph no longer collapses to a dot when scrolled with a mouse wheel. The graph library zooms a fixed ten percent per wheel _event_, ignoring how far each event says it scrolled — and a smooth-scrolling mouse or trackpad reports one flick as dozens of tiny events, each taken as a full ten-percent step, with an internal floor of 0.00001× that the buttons' own 0.05× limit never allowed. One flick could therefore shrink the entire library to a sub-pixel speck with no way back but the fit button. The page now handles the wheel itself: zoom is proportional to the reported scroll distance (with line- and page-mode deltas converted to pixels), a single event's effect is capped so a free-spinning wheel cannot teleport the view, the range is clamped to the same 0.05×–5× the zoom buttons use, and the point under the cursor stays under the cursor while zooming.

- Broken GeeksForGeeks imports are now found, repaired where possible, and surfaced for review instead of silently rotting. The profile page's links drift across GFG's three slug generations, and GFG serves a live-looking page for dead URLs — so an import could store slugs that match nothing, and every downstream system paid for it invisibly: the background repair pass burned all five of its retry slots per broken record and then gave up forever, and Code Recovery opened a tab per record and waited out the full 30-second timeout for a page that could never contain code. GFG's practice API, unlike its website, answers a wrong slug with an honest 404, so each imported problem is now checked against it right after the import (and before the backdated commits run): a slug that resolves is stamped verified, a wrong one is repaired by trying the known generation variants — the record's identity and any files already in your repository are untouched, only the link is fixed — and one whose every variant is definitively gone is flagged as broken. Flagged records are excluded from the repair pass, Code Recovery and metadata refreshes, and the library shows a banner counting them with a Review dialog: open each link yourself, re-check it against GFG (problems do come back), and remove only the ones you select, behind a confirm. Nothing is ever deleted automatically, and a network failure during checking never counts as proof a problem is gone. An import always recorded when each problem was actually solved, but nothing committed on those dates unless you found Library → Settings → Git → "Sync to GitHub" and pressed it within ten minutes — after which the maintenance retry swept everything into one commit dated today, flattening months of history into a single green square. The GeeksForGeeks import now starts that backdated sync itself the moment the last batch lands (one commit per problem, oldest first, running in the background), the LeetCode import's own "Commit to GitHub" button was quietly using the date-flattening mode and now uses the backdated one, and while an import is still feeding batches in, the ten-minute retry and any manually-triggered bulk sync defer to the backdated mode instead of racing it. The suppression is a timestamped window each batch renews, so a crashed import can never hold the retry off for good; and an interrupted backdated sync still resumes after the browser reopens, as before.

- The "N solves haven't reached GitHub yet" banner (and the toolbar `!` count) no longer counts phantom entries forever. The pending-commit marker embeds the language in its key, so a problem whose language was filled in after a bulk import — by self-heal, code recovery or a metadata refresh — left its original marker orphaned: no code path could ever match it against a current problem and clear it, and the count only grew. The ten-minute maintenance resync now garbage-collects any stale marker that no local problem can generate, so an inflated count drains itself on the next tick.
- The README's header shields no longer reset to zero once your repository grows. The Solutions / Easy / Medium / Hard numbers are baked into the README each time it is regenerated, from a re-read of the repository's own `index.json` — and the API that serves that read inlines nothing over 1 MB, which a full index crosses easily. Past that point every rebuild read "no stats" and wrote literal zeros over your real numbers, permanently. The regeneration now takes its numbers from the fresh `index.json` inside the very commit being built, which is never stale and has no size ceiling; the re-read path, still used when a rebuild carries no index of its own, falls back to the blob endpoint (100 MB limit) instead of giving up. The header also gained two shields that were planned alongside the difficulty ones: **Languages** and **Platforms**, counted from the same breakdowns the stats section already shows.

- "Open on GeeksForGeeks" links work again for problems solved recently. GFG's modern problem URLs carry a double-hyphen id — `geeks-island--170646` — and the slug normalizer, written for the legacy generation where `total-decoding-messages--1235` really did mean `total-decoding-messages1235`, collapsed the modern form the same way, producing an address GFG answers with an empty shell. The two generations are distinguishable by id width (legacy ids are at most four digits, modern ones at least five — verified against the live site, including today's problem-of-the-day slug), and the normalizer now leaves the modern form alone. The import's cleanup pass had the matching mistake: it read any stored slug containing `--` as a corrupt legacy import and deleted it, which on a modern problem meant deleting the correct record — it now deletes only records whose slug normalization would actually change.

- The GeeksForGeeks import no longer mangles titles or wastes a signed-out run. Titles arrive from the profile with internal IDs appended ("Compare Two Fractions 4438 102404"), and the old cleanup stripped _all_ trailing digits — turning "Power of 2" into "Power of". Only whitespace-separated runs of four or more digits are IDs, and only those are stripped now. An import that could not read your handle used to post the placeholder "Anonymous" to the submissions API and walk 18 throttled, empty months for nothing; it now skips the date pass and marks those solves undated. The completion message also says, when Code Recovery is switched off (its default), that imported problems will stay code-less until it is enabled in Settings → Advanced — previously the import looked finished while silently never fetching any code. The `dev/import-profile/gfg-importer.js` CLI, which printed a success line while importing nothing, now says plainly that it is not implemented and points at the extension's own Import All Solves button.

- A solve whose language cannot be read is now committed as a `.txt` file named honestly, not as a fabricated C++ one. Codeforces and GeeksForGeeks both defaulted to "C++" whenever the page's language selector was missing or unreadable, so a Python solution whose selector had moved arrived in the repository as `two-sum.cpp`. All six of those fallbacks are gone; an unreadable language flows through each platform's resolver and comes out as `unknown`/`.txt`, which says what actually happened.

- A second solve landing while one is still being committed is no longer dropped. Codeforces, NeetCode and takeuforward deliver each accepted submission as a one-shot event, and the lock that stops a commit racing itself used to discard any event that arrived while it was held — gone for good, because unlike the poll-driven platforms nothing re-detects it. Those handlers now queue the event behind the in-flight commit and process it as soon as the lock releases; the existing dedup keys make a replayed duplicate a no-op rather than a double commit.

- A metadata-refresh run interrupted by the browser suspending the extension's service worker now resumes where it stopped. The queue of background tabs lived only in memory, so a suspension mid-run silently abandoned the remaining problems and could strand an open worker tab with nobody listening for it. The queue is now kept in session storage and picked back up on the next wake, including noticing when the in-flight tab died while the worker was asleep.

- Two smaller repairs in the canonical-map cache: its "how fresh is this" clock is persisted instead of resetting on every service-worker wake (which had turned the cache lifetime into "refetch on every wake"), and a not-modified answer from the CDN now actually loads the cached copy into memory — previously a fresh wake that got a 304 ran with only your local entries and none of the shared map. Chat-history imports also now deduplicate inside their own transaction, so retrying an interrupted import cannot store the same conversation twice.

- The README badges and shields no longer show 0 out of nowhere. Two writers produce those numbers — the extension when it commits a solve, and a nightly workflow in your own repository that keeps the streak honest on days without commits — and both had a way of arriving at zero. The workflow ran a bundled copy of the scoring rules that had quietly fallen behind the extension's own: nothing regenerated the bundle when the rules changed and nothing checked it, so an import whose solve dates the platform never published scored as nothing overnight after counting correctly all day. The bundle is regenerated, a test now fails the build the moment it goes stale again, and the workflow refuses outright to overwrite the badges when its recompute says zero solves while the index plainly lists some — bad data reads as "leave the badges alone", not as a broken streak. On the extension side, a transient storage failure while assembling a commit used to be treated as an empty library, which published an all-zero snapshot over your real one; the badge build now skips that commit instead, and the next one corrects it.

- Topic chips no longer appear twice on a problem. Enriching a problem from the shared canonical map unions the map's tags with the stored ones before normalizing either, so the map's `array` and the platform's `Array` both survived the union as different strings — and then normalized into the same label, showing every canonical topic twice in the problem dialog, on cards and in the graph inspector. The read paths now dedup after normalization, the same order the save path already used.

- Roadmap milestones no longer sit at zero while you solve exactly what they ask for. A milestone is scored by matching its topics against a problem's tags, and the two were being compared in forms that could never meet: the milestones are written as slugs — `hash-table`, `depth-first-search`, `heap-priority-queue` — while every platform stores the tag text it displays, so LeetCode sends "Hash Table" and "Depth-First Search". Matching lowercased the tag and nothing else, so it succeeded only where the tag happened to be one word. "Array", "Greedy" and "Trie" counted; everything else was stuck at 0 of 12 no matter how much work went into it, which reads as a broken progress bar rather than as a bug. Both sides are now folded to the same form before comparing, which also joins the platforms up: a topic counts once, whether the tag came from LeetCode, NeetCode or takeuforward, and however that site spells it.

- A private repository no longer gets a README of broken badges. Enabling GitHub Pages is a request that can fail — most often because Pages is a paid-plan feature when the repository is private, so on a free account it is not merely off, it is not offered — and the setup step recorded the address the site _would_ have had regardless, without checking that one had been served. Every badge in the README is then built on that address, so each one resolved to a 404. Only a URL GitHub itself returns is recorded now; with none recorded the badges are addressed relative to the repository, which needs no Pages site at all, and the README's header links to the repository rather than to a page that cannot exist. The setup step also reads your plan from the sign-in response it already makes, so the private-repository option explains up front what it will and will not get you.

- Dropdown menus no longer open as a white list over the dark page. Every `<select>` in the library left its colour scheme unstated, so the browser drew its native popup for a light page — white background, pale options, near-unreadable against the dark UI. The stylesheet now declares the dark scheme for selects and paints their options to match the rest of the page.
- The graph's platform filter now lists every platform the ledger actually contains. The dropdown was hardcoded to LeetCode, GFG and Codeforces, so NeetCode and takeUforward solves could never be filtered by platform. A round of small graph polish rode along: a select with an active filter lights up so a filtered view explains itself, the search box gained a visible clear button, the collapsed legend chip previews the colours of whichever colour mode is active instead of always showing difficulty, and an empty graph now says where solves come from instead of one flat line.

- The README's shields no longer break when the Pages site moves. The site's address was recorded once, at onboarding, and every badge URL was built on it forever — but a Pages address is not permanent: add a custom domain to the repository (or to any repository of yours, since a user-site domain re-roots every project site under it) and GitHub starts serving the badges somewhere else, while the README keeps pointing at the old address. In the worst case that old address now belongs to a different site entirely, which answers every path with an HTML page, and every shield in the README renders as a broken image. The stored address is now re-read from the Pages API before each infrastructure rebuild (at most once a day), so a moved site corrects the README, `badges/config.json` and the nightly refresh workflow's addresses on the next commit — and a Pages site that was turned off downgrades the badges to repository-relative addresses instead of leaving them pointed at a corpse.

- The store listings declared two host permissions they never disclosed. `neetcode.io` and `takeuforward.org` have been host permissions and content-script matches in both manifests since those handlers shipped, while the Chrome, Edge and Firefox copy still described three platforms and justified three hosts — and the Chrome listing's last rejection was specifically for an inaccurate description. All three now name five platforms, say which are stable and which are beta, note that takeuforward's own editor is part of TUF+ while its free sheets link out to other sites, and carry a full account of the network tap those two hosts need: which two APIs it wraps, the fixed endpoint list it matches on, why takeuforward's problem-metadata endpoint is on that list, and the file and array a reviewer should read to check it.
- The Firefox listing said streak badges were refreshed "by a GitHub Action inside the user's own repository, not by the extension". The extension writes the badges itself, in the same commit as the solve; the optional Action only covers days with no solve, and is not installed at all in a private repository unless you ask for it. All three listings also under-counted the background alarms — three queues drain on their own alarms rather than two, and the hourly redraw of the toolbar streak count was not mentioned anywhere.
- The landing page described a smaller product than the one that ships. Its hero said three coding platforms while its own support table said five, streaks and the friend comparison appeared in the page's structured data but nowhere a reader could see them, the comparison page had no link pointing at it from anywhere on the site, and the import section still named only LeetCode and GeeksForGeeks after the Codeforces import shipped. All four are corrected, and the two facts a friend would want before adding anyone — that nothing is written to their repository and that following is one-directional — are now stated in the FAQ rather than left to be discovered.
- Extension detection on the landing page never worked in Firefox and was unreliable everywhere else. Three separate faults. Firefox's Xray isolation makes an object created by a content script read as `null` from the page, so every handshake arrived empty — and the page treated any handshake, empty included, as final, which also switched off its DOM-marker fallback, leaving Firefox with no working path at all. The page attached its handshake listener only after an awaited config fetch, so on a slow connection the content script's retries could all fire before anyone was listening. And the library page was not listed as web-accessible, so even a handshake that did land carried an address the browser refuses to let a web page navigate to — the button appeared and the click died in silence. The handshake detail is now exported into the page compartment (`cloneInto` on Firefox), the listener is armed before anything is fetched, an empty handshake no longer counts as an answer, and the click is relayed to the extension's background instead of depending on navigation.
- The landing page's version was updated by hand, so it advertised whichever release someone last remembered to edit it for. `node dev/sync-manifests.js` now carries the version into the hero badge and the structured data along with the two manifests, and exits non-zero if either string stops matching rather than skipping it in silence.

- Streak badges pointing at a page that does not exist. The self-hosted SVGs are described in Settings → Gamification as working in private repositories, and they can — they sit in `badges/` in the repository itself, and a README can address them from there. What the README was actually given was `https://{you}.github.io/{repo}/badges/…`, a GitHub Pages address assembled from your username whether or not you have ever turned Pages on. A private repository cannot serve Pages at all, so on exactly the repositories the panel promised, every badge was a broken image. The Pages address is now used only when Pages is known to be serving the repository; otherwise the badges are addressed relative to it, which needs no Pages site.
- The repository's own website link ignoring a custom domain. Onboarding sets the repo homepage — the link in the "About" box, the most visible address the repository shows — to the Pages URL GitHub reported at creation time, which is always the generic `{you}.github.io/{repo}` address, because a custom domain can only be configured after the site exists. GitHub never updates that link itself, so a user who later put their own domain on the site kept a repository whose front door pointed at the retired address forever, while the README and badges — which re-read the Pages URL daily — had long since moved on. The daily re-check now brings the homepage along with them. It only rewrites a homepage CodeLedger plausibly wrote — empty, the previously recorded Pages URL, or the generic Pages address; a homepage you typed yourself is never touched, and a failure to update it is logged rather than allowed to cost the commit it rode in on.
- `worker/wrangler.toml.example` would deploy a Worker that serves nothing. It declared static files with the older `[site] bucket` form, which binds `__STATIC_CONTENT`, while `worker/src/index.js` reads `env.ASSETS` — so anyone who copied the example and deployed it got a 404 on the landing page, `/compare`, and every other static route. It now declares `[assets]` with `binding = "ASSETS"`, matching the deployment this repository actually runs. The same file, and the Worker's own header, listed the pre-OAuth `CODELEDGER_GH_APP_*` secret names as the ones to set; both now name the `CODELEDGER_OAUTH_*` names, note that `SESSION_SECRET` is required rather than optional, and say what happens when each optional secret is left unset.

- A Codeforces solve committing the wrong problem, and committing it before the judge had answered. Submitting on Codeforces posts a form and lands you on `/contest/{id}/my` — a table of every submission you have made in that contest, most of them accepted, none of them the one you just made, which is still showing "In queue". The watcher took the first accepted row it saw, so the moment that page loaded it filed whatever you had solved earliest in the contest, using the code you had just written; and because it did not wait for your own row, a run that went on to fail was recorded as a solve. An accepted row now has to link to the problem whose code was captured before it counts for anything, and a capture older than thirty minutes is discarded rather than left in `sessionStorage` all day waiting to attach itself to an unrelated verdict.
- Codeforces problems arriving in the library named after their own slug, with no tags, no rating and an empty README. Same page, second consequence: the verdict is read on `/contest/{id}/my`, where the problem statement is not present at all, so every descriptive field was extracted from a page that had none of them — and the missing title was papered over with the slug, which is why a library filled up with problems called `1234A`. The title, tags, rating and statement are now captured at submit time, while they are still on screen, and carried across the navigation with the code. Nothing is invented: a field the page cannot answer for is recorded as absent.
- The runtime and memory on a Codeforces solve being the language and the verdict. They were read from the fifth and sixth columns of the submissions table, which are those two on `/contest/{id}/my`. They are now read by class name, and a cell that is not there is reported as nothing rather than as whatever sat in that position.
- The `**Source:**` link in a committed Codeforces README pointing at the contest view — a page that does not exist for a gym problem and stops resolving for a regular one once the contest is archived. It now uses the same permanent problemset or gym address every other link in the extension resolves to.
- Codeforces tracking being off in one settings screen and on in another. The platform card special-cased Codeforces to disabled because it was alpha, while the Codeforces section's own "Enable tracking" toggle declared itself on by default, and the handler agreed with the card — so a user who read the second screen and solved a problem recorded nothing, with both screens looking correct. Every platform now defaults to enabled, which is what all three already claimed.
- Every link back to a Codeforces problem being a 404. Codeforces is the one platform with no slug of its own — a problem is addressed by contest and letter, so CodeLedger glues the two together as `4A` to have a single id to store against, and five separate places then pasted that id onto `/problemset/problem/` and produced `/problemset/problem/4A`. The arrow on a problem card, the link in the problem window, the "Refresh problem data" tab, the background metadata refresh and the published stats page were all affected; the refresh paths were the worse of the two, because they opened a page that could never load and then reported that nothing could be read from it. The slug is now taken apart again wherever a link is built, gym problems included, and a slug that cannot be read produces the problem archive rather than a wrong address.
- A Codeforces solve not recording the problem statement that was on screen when it was detected. The handler has always read the statement — it is used when you ask for a problem's data on demand, and it is written into the committed README — but the ordinary solve path dropped it, so the library showed a blank problem and the AI reviewer was told to work without a statement that was sitting in the same page it had just read the code from.
- Two regexes on the published stats page arriving with their backslashes stripped. That page is written out through a template literal, which silently eats a lone `\`: the year filter shipped as `/^d{4}$/`, so picking a specific year in the heatmap matched nothing, and the commit link's `http(s)`-only check shipped as `/^https?://` — which JavaScript reads as a regex followed by a line comment, deleting the rest of that line. The check the code appeared to make, and that a test was reading the source of, was not running on the published page at all. Both are fixed, and the test now runs the emitted page's own function instead of matching text that can survive as a comment.
- Codeforces solutions written in C committing as `.txt`. Codeforces names its C compiler "GNU C11", and the language matcher looked for a standalone `c`, which the version suffix prevents from ever matching. An unrated Codeforces problem was also recorded as Easy rather than as unrated, because an empty rating counts as zero.
- Every conversation held in the floating AI panel being lost the moment you left the page. The panel runs as a content script, and a content script's IndexedDB belongs to the _site_, not to the extension — so `CodeLedger_AIChats` opened on leetcode.com was leetcode.com's database, and the library, which runs on the extension's own origin, was reading an entirely different one. The write succeeded and reported success every time, which is why nothing ever surfaced it: the panel showed the chat saved, the AI Chats tab showed nothing, and neither was lying about what it could see. The panel's reads and writes now go through the service worker, which is on the extension's origin and has the real store. Conversations written before this are in the page's own database, where nothing can reach them; they are not recoverable.
- The floating AI panel not being able to see your code on NeetCode and takeuforward. Both handlers overrode the panel's editor reader with one that returned an empty string, so the assistant on those two sites was answering about a solution it had never been shown — it could see the problem and your messages and nothing else. Both use Monaco, which the panel already knows how to read.
- One bad request burning every API key you own. A key was put into a one-minute cooldown on _any_ failure — a model name with a typo, a malformed prompt, an empty response — and because the provider loops over the whole pool, the first such error walked down every key in turn and cooled each one, ending in "All API keys are currently in cooldown (rate-limited)". That sentence names the one cause it was not, and sent people looking for a quota problem they did not have. Only 429 (the quota itself) and 503 (the model temporarily out of capacity) now cool a key down; waiting does not fix a 400, so a 400 leaves the key in rotation and the real error is reported.
- Behaviour bank records showing an unreadable fragment where the review's point should be. The stored summary was the first 200 characters of the review, which is always its heading and the opening of its complexity table, cut mid-word — one read `### Analysis **1. Complexity** * **Time Complexity:** $O(N \log N…`, which tells you nothing about the problem it belongs to. Reviews now end with a one-sentence takeaway written by the reviewer itself, and that is what is stored. Records saved before this have their markdown rendered rather than shown raw, which is as much as can be recovered from a fragment.

- The assistant answering "No active roadmap set" to someone looking straight at one. The Roadmap tab writes to the roadmap store; the two tools that read and write roadmaps for the AI used a settings key nothing has ever written, so they could not see a roadmap the tab had saved, and a roadmap the assistant created could not be seen by the tab. Both now use the same store, and both score progress with the same counter the tab displays, so the two can no longer disagree about how far along you are.
- Skills switching themselves on uninvited. Trigger matching was a plain substring test, so pasting a link containing `/review` put the assistant into review mode, and the word "helper" in a sentence started the hint ladder. A command now has to be typed as a command, and a keyword has to appear as a whole word.
- "⚠ 86 conflicts detected during background sync" sitting directly above "Repository is already in sync — no new problems found", with no way to tell which was true. Two separate faults. The comparison that decides what a conflict is treated every way of writing "nothing" as a different value, so a record saved before `tags` existed disagreed with the same record saved today (`[]` versus absent), and `isDuplicate: false` disagreed with no flag at all — enough to flag an entire untouched library for manual review. And the warning banner reads its count from settings the panel holds in memory, which the import path cleared in storage but never told the panel about, so a count that was already zero stayed on screen. Absent, empty and `false` now compare equal, whitespace no longer counts as a difference, and re-checking a stale warning says in words that the conflicts are gone.
- Importing a GeeksForGeeks profile dating every problem to the day you imported it. The profile lists what you solved but never when, and the importer filled the gap with the current time — so a back catalogue of 200 problems became 200 commits dated today, one solid block on the contribution graph, and 200 solves stacked on a single square of the heatmap. Solve dates now come from GFG's month-scoped submissions endpoint, earliest submission wins, and the walk stops as soon as every problem has a date. Anything it still cannot date is recorded as undated rather than guessed: it earns its points and counts as a solve, but belongs to no calendar day, and all of the undated problems land in one clearly-labelled commit instead of one commit each.
- Pressing "Fetch Description" on a LeetCode problem moving that solve to today's date and, if the fetch came back without tags, emptying the tags it already had. The refresh looked the problem up by its bare slug where the records are keyed `lc-two-sum`, so it never found the one it was about to overwrite and treated every field as new — including the date, which it stamped with the moment of the refresh. Same shape of fault as the GeeksForGeeks import dates above, in a different place: a repair that quietly rewrote history. The lookup now uses the real key, tags survive a fetch that returns none, and a solve with no recorded date keeps having no recorded date rather than claiming to have happened during the refresh.
- A solve whose stored timestamp was `null` or `0` being scored on 1 January 1970 — a real date, on the calendar, inside the heatmap range, and eligible to be your best day.
- Badge SVGs never appearing in the repository, and the streak reading 0 in the popup, on the toolbar icon and in the badge preview. All three read the solve list through `Storage.getProblems()`, which has never existed — the accessor is `getAllProblems()`. Each call sat inside a `try`/`catch` written for "badges are decoration, never cost someone a commit", so the resulting error was logged as non-fatal and the badges were silently skipped on every single commit. A test now checks that every `Storage` method called anywhere in the source actually exists.
- Easy / Medium / Hard reported as 0 on the published stats page, in the badges and in the popup, above a non-zero total. Four separate places counted difficulties by comparing to the literal string "Easy" — which misses every GeeksForGeeks School and Basic grade, every Codeforces numeric rating, and anything renamed through your difficulty map. They now share one counter that normalizes first and reports what it could not classify as `unknown` rather than quietly filing it under Easy. The published report also counts its own problem list in preference to the stored totals, so an existing repository corrects itself on the next page load instead of waiting for the next solve.
- The published stats page rendering as a wall of raw JavaScript below the charts. A comment explaining that commit data must not contain a closing `script` tag spelled that tag out literally; the HTML parser does not know what a JS comment is, so the element ended there and everything after it was painted onto the page as text. The escaping test only ever checked injected data, never the template's own prose, so it passed the whole time the page was broken — there is now a test that the script blocks open and close in strict alternation.
- The activity heatmap on the published report overflowing into a horizontal scrollbar. Sizing measured the padded card rather than the scroll area, so it handed the grid roughly 3rem that does not exist, and it counted one inter-column gap too many.
- The knowledge graph settling into a knot of overlapping circles with the labels smeared over each other. Three causes, all geometric. Link lengths were measured centre to centre, so a problem's resting place next to a busy topic — a hub is drawn up to 48px across, the rest length was 60 — was _inside_ the circle it belongs to; they are now measured rim to rim. Nothing ever guaranteed nodes stayed apart, because repulsion only ever makes overlap less likely, so a separation pass now resolves any remaining overlap on positions directly. And every label was drawn regardless of whether another one was already there; a label that would collide with one already placed is now dropped, with the selected node, the hovered node and its neighbours taking precedence. The layout arithmetic moved into its own module so those are properties a test can check rather than something you have to squint at.
- Backups that reported success without having run. `commitBackupToGitHub` caught every error and returned normally, so the "Backup now" button printed "Backup committed to GitHub." after an expired token, a rate limit or a repository that had been renamed — and the automatic backup that runs every N solves could fail for months while the panel looked exactly the same as if it were working. The commit now throws when it does not land, the button names the file it wrote and how many older ones it pruned, and the outcome of each route — the copies on this device and the ones in your repository — is recorded and shown at the top of Settings → Backups with the reason when it failed. A failed automatic attempt now retries on your next solve instead of waiting out another full interval.
- Local backups quietly stopping once your history outgrew 10MB. The extension keeps up to sixteen snapshots on the device — ten manual, five automatic, one always-current — and each holds the full text of every solution, so a few hundred problems is enough to exceed Chrome's default `storage.local` cap. The write then failed, the failure was logged to a console nobody has open, and the "backup" you were relying on was months old. The extension now requests `unlimitedStorage`, which grants access to nothing new and only lets the data you already have be stored whole, and a write that fails for any other reason now says so on screen.
- Every file read back out of your repository being decoded as if it were ASCII. Eleven places — the sync index, the settings and chat mirrors, the backup snapshots, the migration reader, the published-report builder — decoded GitHub's base64 with bare `atob`, which returns one character per byte. A problem title with an accent, a comment in a language other than English, or an emoji in a note came back as mojibake, and the mangled text was what got written on the next commit, so a single bad character became permanent and compounded on every round trip. They all now share one UTF-8 decoder.
- Two full snapshots of every problem, source code included, being built out of the database on each solve — one for the rolling backup and one for the scheduled copy, both of the same data. One build now serves both.
- Sign-in failing with "The client_id and/or client_secret passed are incorrect" after the credentials were set. Two causes: whitespace left by pasting a value into `wrangler secret put` survived into the stored secret, and the authorize step trimmed it while the token exchange did not — so sign-in appeared to work and then failed at the last step. And the client ID and the client secret resolve through separate lists of accepted variable names, so setting the ID under one name while an older secret remained under another paired two different applications' halves. Both values are trimmed now, and a rejected pair reports which variable supplied each half.

### Security

- Bumped puppeteer from 24.x to ^25.8.0, which drops `extract-zip` from the dependency tree entirely — the version we carried had an unvalidated-symlink path traversal (Dependabot alert #89) with no patched release of its own. Development-only dependency: puppeteer is used by the headless QA scripts and never ships in the extension or the worker, but a `npm install` on a contributor's machine is still a machine worth not traversing.

### Removed

- The **Codeforces handle** field in Settings → Platforms → Codeforces, which said it was "reserved for future profile import support" and did nothing. The import shipped and reads the handle from the profile page you are standing on, so the field has no reader; a setting that stores a value nothing consumes is worse than no setting, because it looks like a step you have to complete.

## [1.7.0] — 2026-08-11

First public release. Versions up to 1.4.7 were development and store-review
builds; see [Development history](#development-history) for those notes. The
version does not restart at 1.0.0 because a `v1.0.0` tag already exists and the
Chrome Web Store requires each upload to exceed the last.

### Added

**Solve capture**

- Platform handlers for LeetCode, GeeksForGeeks, and Codeforces that detect an accepted submission and capture the code, language, difficulty, tags, and runtime/memory figures.
- A floating stopwatch on problem pages; the elapsed time is recorded with the solve.
- Bulk import of past solves from a LeetCode or GeeksForGeeks profile you own.
- On-demand code recovery for solves whose source was not captured at submission time.
- Duplicate detection, so re-submitting the same solution updates the existing entry instead of creating a second one.

**GitHub**

- One atomic commit per solve through the Git Trees API — solution file, README, and the repository index land together or not at all.
- Repository setup wizard: create a new repository or link an existing one, then write the initial layout in a single commit.
- A generated GitHub Pages dashboard in the repository showing a solve heatmap, language and topic breakdowns, and a searchable problem table.
- Cross-device sync through the repository's `index.json`, with a conflict resolver for entries that changed in two places.
- Mirror repositories: a commit that fails against the primary target falls through to a configured mirror rather than being lost.
- A **Connection check** in Settings → Advanced that answers "why is nothing being committed?" in one press. It reports the four things that have to be true in the order they matter — a token is stored, GitHub still accepts it and says what it can do, the repository exists and this token can push to it, and something has actually landed there — and each line that is not green says what to do about it. It draws the distinctions the old error message could not: a token that reports no scopes is a GitHub App token or a fine-grained PAT, and only the first of those is unable to create a repository; a 404 on the repository means either it is missing or this token cannot see it, and it says both rather than guessing.

**AI**

- Code review from Gemini, OpenAI, Claude, DeepSeek, OpenRouter, or a local Ollama model, using your own API key.
- A review queue that retries with backoff and respects provider rate limits, so a burst of solves does not drop reviews.
- A floating chat panel on problem pages with `/` commands for pulling in your code, the problem statement, and your errors.
- Chat history stored locally and, optionally, synced to the repository as Markdown.
- A tool panel in the chat view that runs fifteen context tools against your own ledger on request — query your solves, find similar problems, analyse a trend, suggest what to practise next, and read and write the behaviour bank. You pick the tool; each one can be switched off. The model does not call them on its own.
- With no provider configured, every AI surface is gone rather than idle — no review panel on problem pages, no chat tab, no queue banner, and neither the AI Chats nor the Behaviour Bank tab in the library, the latter holding nothing but insights and skills written by and for a model. Reviews you already have stay readable and filterable, because that text is yours. Adding a provider brings the surfaces back without a reload.
- The chat reads the behaviour bank the same way the review does. How long you took, how many attempts it took, and what a previous review flagged were being recorded on every solve and then only ever shown to the reviewer; the assistant you are talking to now gets the same history for the problem in front of it.

**Library**

- A sidebar and full-page library listing every captured problem, with search, filters, and per-problem detail.
- Analytics: solve heatmap, topic radar, difficulty breakdown, solve velocity, and language distribution.
- A force-directed knowledge graph linking problems through shared topics.
- A canonical topic map so the same concept from three platforms lands under one name.
- Topics are split onto two axes — data structures and algorithms — everywhere they are counted, because ranking them together lets Array bury Dynamic Programming. Which axis a topic sits on is a judgement call — Binary Search is a technique, Binary Search Tree is a structure — so the canonical topic list in Settings → Platforms lets you overrule any of them, and everything that counts topics follows your call instead.
- A **Where the gaps are** panel in Analytics that ranks topics by how well you hold them rather than by how often they turn up: solve count saturates, time since the last solve decays, and the two multiply. Structures and algorithms are ranked in separate columns, well-known topics with no solves at all are listed as blind spots, and one number up top says what share of your solves needed a technique rather than just a structure. Any row opens the solves behind it.
- The knowledge graph can colour topics by mastery instead of by identity. Giving every topic its own hue makes a pretty picture of what you have tagged and answers nothing; the mastery colouring spends the same colour on how well you hold each topic, so the weak areas are the ones that stand out. Switching mode repaints in place — the layout stays exactly where you left it — and a selected topic now shows how many problems you actually solved under it, when you last did, and how solid that leaves it. That solve count no longer includes the unsolved suggestions hanging off the topic.
- Behaviour bank recording how you interact with problems, with a switch in Settings → Advanced that stops the recording.
- Backups: manual JSON export, scheduled snapshots, and a snapshot before any bulk import.

**Streaks and badges**

- Points per solve on a fixed scale — Easy 10, Medium 25, Hard 50 — so the number means the same thing in your ledger as in anybody else's. Re-solving a problem you already have earns 40% of the first solve, and only after a three-day cooldown, which pays for spaced repetition without making one easy problem farmable.
- A daily points target (25 by default, adjustable) closes the day and keeps the streak alive. Doubling the target banks a streak freeze, up to five; a missed day can be bought back the next day at 1.5× the target.
- Vacation mode, with a three-day ramp at half target afterwards rather than dropping you straight back onto the full one.
- Ten levels and a set of achievements, both derived from the ledger.
- The achievements now have a shelf in the library's Analytics tab, locked ones included, instead of only appearing in the README the extension writes. Two of them count reviewed solutions, so they show up once a review provider is configured; with none configured they stay out of the list rather than sitting there permanently unreachable, and any you already earned keep their place. Anything earned since your last visit to the shelf is marked; the first visit marks nothing, because a back catalogue is not news.
- Streaks start the day you install. An imported back catalogue contributes its points but does not invent a streak you never lived through.
- The toolbar icon carries the current streak, coloured by whether today's target is already in, and the tooltip spells out the rest. The popup shows the same numbers with today's progress and what a rescue would cost.
- Badges are generated as SVG files committed into your own repository, with a `badges/stats.json` beside them. Nothing is fetched from a badge service, so a private repository works the same as a public one, and there is nothing to pay for or keep running.
- The streak card is committed in a light and a dark cut, and the README block uses a `<picture>` element so GitHub serves whichever matches the theme the reader chose. The bar and the numbers animate once as the card loads, and not at all for a reader whose system asks for reduced motion.
- A **Share** button on the analytics streak card. It renders the same card to a PNG in the page — copy it to the clipboard or save it — alongside an editable sentence and one-click links to X, LinkedIn, and Reddit. The links are each site's own public composer URL, so nothing is uploaded anywhere and no account beyond the one you are posting from is involved. A private repository is not linked in the post, because that link is a 404 to everyone who reads it.
- An optional GitHub Actions workflow refreshes the badges once a day, at an hour you pick, so a streak reads correctly on a day you have not solved yet.
- The whole feature has one switch. Turned off, solves are captured and committed exactly as before and every streak surface disappears — including the toolbar badge. The welcome page offers the choice before the first streak exists.

**Party**

- A **Party** tab that lines your ledger up against other people's. You add somebody by writing down their public repository — `owner/repo` or a pasted link — and the extension reads the `badges/stats.json` their own copy commits. There is no server, no account, and no request to be accepted.
- Rank by points, current streak, longest streak, solves, or level. Opening one friend pulls their full ledger and shows platforms, difficulty spread, top topics, and — the part worth having — the topics they cover that you do not.
- A share button mints a `codeledger.vkrishna04.me/compare?repos=…` link. The link carries the list and nothing else, so whoever opens it sees exactly what you saw without installing anything.
- The tab says plainly what it is: one-sided, since adding somebody does not add you to their list and they are never told; and self-reported, since the file lives in a repository its owner controls.
- Your friend list travels with the rest of your settings, so a second device does not start from an empty list.

**Privacy**

- A **Settings → Privacy** page that names every destination your data can reach: your GitHub repository, the sign-in relay, anyone with the link if the repository is public, the badge SVGs, the generated Pages site, `shields.io` if you pick that badge style, each AI provider you have configured, `mermaid.ink` when you press Render on a diagram, the repositories you add to Party, and the anonymous solve counter.
- The page opens with the tier your current setup is actually in — Private, Shared, Public, or Code leaves — followed by what is live now and what is available but switched off. Every row says what leaves, where it goes, and links to the panel that turns it off.
- The list is computed from your settings rather than written down, so it cannot fall out of step with what the extension does. The welcome page shows the same summary during setup.

**Both browsers**

- Chrome and Firefox from one source tree, with every extension API call routed through a single compatibility shim.
- The download is 3.5 MB rather than 17 MB. The packager copied all of `assets/images/`, which is mostly store promo tiles, a social preview and a screenshot of every tab — none of it opened by anything the extension runs. It now ships the four icons the manifests declare and the three branding images that get committed into your repository, and nothing else. The unpacked build applies the same rule, so what you load locally is what ships.
- The release command refuses to cut a release over a failing check. It now runs the type gate, the full test suite and the sync regression script, and stops on the first failure; previously it ran only the last of the three, inside a `catch` that turned a failure into a printed warning. It also verifies the Firefox manifest's version, which nothing checked before, and pushes the branch you are actually on rather than whatever `main` happens to point at locally.

### Security

- All third-party HTML — problem statements scraped from platform pages, AI responses, model identifiers — is reduced to an attribute-free allowlist of formatting tags before it reaches the page. Statements render inside a content script, where markup would otherwise execute in the host page's context.
- The OAuth callback signs its `state` parameter, stores it in an `HttpOnly; Secure; SameSite=Lax` cookie with a ten-minute lifetime, and compares it in constant time.
- The authentication worker exposes no endpoint that mints GitHub App installation tokens.
- Repository paths built from scraped titles are constrained: no `..` segments, no leading dots, no path escapes.
- **AI provider API keys could be written into your repository.** Settings sync waves through every key belonging to a provider — `openai_enabled`, `claude_model` and so on — so that a second device gets the same setup. `openai_keys` is one of those keys, and it is where the provider card puts what you type while you type it, before you press Save. An API key entered and not saved could therefore be committed to `.codeledger/sync.json` and `.codeledger/config.json`, in plaintext, in a repository that is usually public. Anything ending in `_keys`, `_token`, `_secret`, `_apiKey`, `_api_key` or `_password` is now refused regardless of which provider it belongs to, both on the way out and on the way back in, and the next settings commit rewrites both files without it. **Git history is not rewritten by this: if you entered an API key in a previous version, rotate it.**
- Reading a sync file back applies the same test as writing one, so a file written by an older build cannot reintroduce a key this one would refuse to send.
- The API-key box no longer writes to storage while you type. It is a staging box — nothing has ever read your keys from there, the providers read them from where **Save** puts them — so keeping a plaintext copy in the settings map bought nothing and was the reason a key could travel anywhere at all. Keys left stranded in settings by an earlier version are moved to where Save would have put them, and then removed; you do not lose them.
- Mermaid diagrams in AI responses are shown as source with a **Render diagram** button. The diagram is only sent to `mermaid.ink` when you press it, because that source describes your problem and your solution.

### Changed

- The default OAuth scope is `public_repo,workflow`. Creating a private repository needs the wider `repo` scope, which the settings panel offers as an explicit one-click upgrade rather than requesting up front.
- The extension no longer wakes in the background when it has nothing to do. Two of its periodic timers existed only to notice an empty queue — one of them checking every minute, indefinitely, for work that only exists after a profile import. They are now started when something is queued and stopped when it drains.
- GitLab and Bitbucket are gone from the interface and from the package. Their handlers were stubs that threw on every call, so presenting them as options — as a provider, as a mirror target, as an `@gitlab` chat mention — meant offering something that could not commit.
- The privacy policy and the store listings now describe the party comparison and the shared `/compare` link, which had been shipped without appearing in either. The policy also stops claiming that local storage is encrypted at rest; browser extension storage is isolated from other sites and other extensions, but it is readable by anyone who already has the operating system profile, and it now says so.
- The privacy policy exists in two copies — `PRIVACY.md` and the page at `/privacy` — instead of five. The three copies embedded in the store-submission documents had drifted; each still described a telemetry payload shape the code does not send. They are replaced by pointers to the canonical text.

### Removed

- Eighteen modules that shipped in the package but that nothing imported, including an encryption helper with a hardcoded salt that no code path ever called. Every line in the package is now a line something runs.

### Known limitations

- GitHub is the only working repository provider.
- The library runs inside the extension. It is not currently served as a standalone web application.
- Telemetry is off unless you turn it on, and sends only the extension version and which platform a solve came from.

### [1.4.6] — 2026-06-18

### Fixed

- **GitHub OAuth broken by COOP** — GitHub sets `Cross-Origin-Opener-Policy: same-origin`, which clears `window.opener` in the OAuth popup. The callback page now embeds auth data in a DOM element (`#codeledger-auth-result`); the `presence-marker.js` content script reads it at `document_end` and relays it to the background service worker via `CODELEDGER_AUTH_RELAY`, which then broadcasts `CODELEDGER_AUTH` to all open library tabs. A `tabs.onUpdated` background pull with a 15-attempt retry loop keeps the Chrome service worker alive for the full ~7.5 s window. This fixes both "cannot login" (v1.4.5) and "cannot create repo after login" (v1.4.4).
- **Conflict modal reappears after resolution** — Root cause fixed: `applyImport()` now stamps each resolved problem with `_conflictResolvedAt: Date.now()`. ### Fixed

- **`import()` banned in MV3 service workers** — all dynamic `await import(...)` calls inside `service-worker.js` removed and replaced with top-level static imports. - **422 non-fast-forward on sequential commits** — `GitHubHandler.commit()` now retries up to 3 times (500 ms, then 1 000 ms back-off), fetching a fresh ref and rebuilding the tree on each retry.
- **Stale `index.json` showing 0 problems after full sync** — a repair commit is now issued when the remote index contains an empty `problems: []` but local problems are already committed.
- **Repo name forced to lowercase** — `GitHubOnboardingModal.js` `sanitize()` no longer calls `.toLowerCase()`; the allowed-character regex updated to `[^a-zA-Z0-9._-]` to match GitHub's actual rules.
- **`/errors` command in AI assistant always showed "no errors"** — raw error string from `readTestFailures()` now passed directly to `expandChatVariables`, bypassing `normalizeList()` which was converting the string to `[]`.
- **Manual sync blocked by submission dedup** — `forceCommit: isManual` now bypasses the `alreadyCommitted` session-storage dedup check so the Sync button always commits.
- **AI floating panel overlapping LeetCode's submit bar** — moved from `bottom: 70px` to `bottom: 110px`.

- **GitHub avatar showed a placeholder instead of the real profile image** — avatar is now hydrated from saved settings on startup and stored as a data URL when OAuth can fetch it.
- **Console logging was noisy when debug was disabled** — `console.log` / `console.error` are now gated behind the debug flag and re-enabled cleanly after OAuth.
- **`index.json` could throw on malformed remote content** — remote sync now guards JSON parsing and falls back to an empty remote index.
- **`providerId` could be undefined in the AI review loop** — the provider id is now scoped before use and falls back safely.
